# ADR-0011：定制 Pi、Codex、Claude Code 三内核工作台

> 2026-09-17 决策更新：内核/渠道及 KSCC 过渡策略已被 [ADR-0012：官方多内核与 API 渠道解耦](ADR-0012-official-runtimes-api-channels.md) 取代。以下保留为原阶段设计记录，不再按“KSCC 作为第三主内核、外部渠道必为 Pi”继续开发。

> 日期：2026-09-16  
> 状态：产品方向已确认；首期手动切换代码已集成，聚焦检查与构建通过，尚未通过真实账号端到端验收。下文为目标设计，不代表全部功能已完成。  
> 决策关系：取代 ADR-0010 的“Pi 唯一主会话、其他仅为配角”限制，以及 ADR-0008 中冲突的默认内核策略。原生协议、认证边界、Chat/Work 权限原则继续沿用。

## 1. 一页结论

**TAgent 定位为多 Agent 工作台，首批支持定制 Pi、Codex、Claude Code（含 KSCC 接入）。Pi 默认，但不再是唯一可处理主会话的内核。**

公司同时提供 API Key 和 Agent 账号资源。用户应能在某个 Agent 慢、断联或表现不合预期时，方便换另一个继续工作。用户感知的质量下降不直接等同于服务商降级，首期由用户判断和切换。

近期价值是“能换内核、聊天和成果留下来”。先实现同一会话手动切换，再扩展多个 Agent 同时执行，不把自动故障转移或完整执行现场迁移作为首期前提。

| 内核 | 定位 | 首批接入方式 |
| --- | --- | --- |
| 定制 Pi | 默认 Agent，承载深度定制和 API 多模型能力 | 复用 PiAgentAdapter 与 pi-core |
| Codex | 可独立处理主会话，跟随官方执行循环 | 复用 Codex App Server；不以一次性 CLI worker 替代主会话 |
| Claude Code / KSCC | 保留现有使用路径，逐步解耦公司接入 | 先复用 Claude Agent SDK + KSCC；标准 Claude Code 单独验证后启用 |

三内核是产品分组，不代表 KSCC 与标准 Claude Code 的配置、版本和协议完全等价。Grok 等 API 模型先通过 Pi 使用，新增独立 Agent 内核另行排期。

## 2. 产品投入与运行边界

Pi 继续定制工具循环、上下文管理和特定场景能力。Codex、Claude Code 保留原生循环、工具和会话协议，TAgent 通过各自适配器接入。

宿主重点建设会话、工作区、工具接入、权限、历史呈现和调度。普通 Codex/Claude Code 对话无需额外调用 Pi 审批或转述；Pi 模型不可用时，宿主仍能切换内核。

```text
TAgent 会话：历史、工作区、执行模式、权限、当前 Agent
  └─ SessionRuntime：发送、切换、状态、持久化
       ├─ PiAdapter → 定制 Pi loop
       ├─ CodexAdapter → 官方 App Server
       └─ ClaudeAdapter → Claude Code / KSCC 接入
```

官方升级可以带来能力更新，但事件、审批、恢复和工具兼容性仍需验证。采用验证过的版本组合，升级失败保留可用版本。KSCC 使用实际分发版本，不能假定可直接套用官方升级。

## 3. 用户入口与自定义配置

会话输入区显示当前 Agent，例如 `Pi · 渠道 A / Grok`、`Codex · 当前运行时模型`、`Claude Code · KSCC`。Agent 选择与模型选择分开；Chat/Work 和权限档继续独立显示。

- **选择 Agent**：决定哪个内核处理后续输入。不可用的选项显示未安装、未登录或不兼容等具体原因。
- **选择模型**：只列当前内核实际支持的模型和渠道；Pi 的 API 渠道不能未经适配直接传给其他内核。
- **执行中换 Agent**：提供“停止并切换”，先停止当前回合；点击选择器不能产生两个同时工作的主执行者。
- **历史呈现**：消息保留产生它的 Agent 标识；切换只增加一条简短记录，交接详情可展开，不重复输出阶段说明。

设置复用现有页面、Agent 目录和角色库：

| 配置 | 内容 |
| --- | --- |
| 渠道与模型 | Pi/API 的渠道、模型、上下文容量和凭据引用 |
| Agent 运行时 | 启用、路径、版本、可用性、原生配置；区分 Claude Code 与 KSCC 接入 |
| Agent 预设 | 名称、内核、可选模型、角色指令、工具与权限偏好；不增加第二套角色系统 |
| 会话选项 | 当前预设、工作区、Chat/Work 和权限档；单次运行冻结实际配置 |

新会话默认 Pi；缺少 API 配置时提示配置或选择其他可用 Agent，不静默换核。旧会话保持原绑定。原生账号认证仍由对应运行时管理，交接数据只保存配置引用。

## 4. 会话与数据归属

产品会话属于 TAgent，各内核保留自己的原生会话。适配器归一发送、停止、文本、工具、审批、错误和结束事件，不转换彼此内部工具协议或隐藏思考。

在现有元数据上增量扩展以下概念，最终字段名随实现确定：

| 概念 | 必要信息与用途 |
| --- | --- |
| 当前执行绑定 | 当前 Agent 预设和 runtime binding；显式选择后不再靠渠道猜内核 |
| 原生绑定集合 | 按内核、配置、工作区区分 native session、版本及最近同步位置，供切回恢复 |
| 单次运行 | runId、绑定、配置快照和状态；事件始终按运行归属落盘 |
| 交接记录 | 来源/目标、历史截止位置、交接内容、附件引用、遗漏说明和投递状态 |

现有 `sdkSessionId`、`codexThreadId` 和 Pi 恢复信息分别迁入对应绑定，不互相覆盖。复用现有 `AgentRun` 契约时需补足审批、停止中和切换中状态；类型存在不等于运行持久化已贯通。

## 5. 首期手动切换

### 5.1 流程

1. 检查目标运行时、工作区和权限是否可用；不支持则保留原选择并解释原因。
2. 当前回合运行中则先停止，确认结束再切换；超时显示停止未确认，不启动新的写入者。已有后台写任务继续受工作区冲突规则约束。
3. 固定历史截止位置，生成并保存交接资料；恢复兼容的目标原生会话，或创建新会话。
4. 原子提交当前绑定和交接待发送标记。界面显示“已切换至 Codex，交接资料将在下一次发送时带入”等实际状态。
5. 用户下一次发送时一并投递交接资料；目标接收后更新同步位置。投递结果未知时显示异常，不自动重发可能执行操作的请求。

切换本身不擅自开启新任务。目标准备失败时保留旧历史与绑定；旧回合已停止则不假装恢复运行。旧实例迟到事件只归档到旧 run，不覆盖新回合状态。

### 5.2 最小交接资料

包含用户目标与最新要求、明确约束、近期对话、重要结论、已有成果路径、相关工具结果和未完成事项。优先从宿主持久化记录组装，不依赖旧 Agent 临时生成总结。

目标容量不足时，保留目标/约束和近期内容，较早历史通过摘要与可访问的历史查询入口补充，明确显示省略范围。摘要模型不可用时采用确定性摘录，仍可切换。附件按目标能力传入，不能只传路径就声称模型已看到图片。

预算按目标内核和模型计算，为回复与工具结果预留空间；未知容量显示估计，不统一写死为 200k。交接资料标明来源，区分用户指令与文档、工具输出，不把旧 Agent 的判断提升为用户授权。

### 5.3 切回与重开

Pi → Codex → Pi 时，旧 Pi 会话可能缺少中间消息。仅在绑定兼容且同步位置可靠时恢复并补入增量，否则新建原生会话并交接。历史显示完整不代表内核已获得完整历史。

重开后恢复绑定、历史和交接记录。上次运行中、停止中或投递状态不明的任务先核实运行状态；无法核实时标记中断/未知，等待用户继续，不自动重放工具调用。

首期保留聊天和工作区、带入必要上下文；不承诺迁移原生思考、运行中的工具或所有历史 token。新 Agent 可以重新核实已有成果。

## 6. 工具、权限与信息流

- TAgent 工具复用现有 handler，通过内核支持的动态工具/MCP 等接口接入；各家原生工具由各家执行。
- 能力声明覆盖附件、工具、审批、停止、恢复、引导和用量。不支持或未知如实展示，不以空实现伪装成功。
- 切换继承当前 Chat/Work 和权限约束。目标无法执行约束时阻止该组合，不通过放宽权限使切换成功。
- 由适配器依据原生执行终态判断完成/失败；可恢复的中间网络错误不抢先结束任务。事件按 run 去重，避免完成消息与阶段内容重复落盘。
- 用量和上下文占用分开记录。切换后展示当前绑定的容量与占用，历史账单可汇总，但不混算为单一上下文。

KSCC 的启动、环境配置和专有依赖收敛在对应适配/构建边界。禁用或不打包 KSCC 时，Pi 与 Codex 仍能独立启动和工作。

## 7. 多模型与并行 Agent

MoA 用于多个已配置 API 模型的分析与汇总，支持跨渠道，不再以 KSCC 一渠多模作为默认前提。

多个 Agent 同时执行复用已有子任务、看板和协作室：短任务走子任务，长任务走看板，持续讨论走协作室。不同运行使用独立绑定；共享工作区先允许并行只读，同一工作区写任务先串行，隔离与合并机制验证后再开放并行写入。

本阶段先完成三内核并列可选。既有协作能力保持可用，新的并行编排入口不作为手动切换的发布依赖。

## 9. 实施顺序与发布验收

| 阶段 | 交付 | 验收门槛 |
| --- | --- | --- |
| A：核实三条路径 | 运行时可用性、能力矩阵、配置整理 | Pi、Codex、现有 KSCC 分别完成多轮、工具、停止、错误和重开恢复，未验证能力明确标识 |
| B：最小手动切换 | 同一会话换 Agent、交接资料、绑定落盘 | 三条路径两两切换及切回，目标/约束能继续使用，历史不重复，成果可访问 |
| C：共用体验 | 工具、权限、附件、长历史和兼容版本管理 | 异常场景回归通过；禁用 KSCC 后 Pi/Codex 可独立使用 |
| D：逐步并行 | 既有任务/看板/协作室复用运行契约 | 独立停止、结果只回投一次、工作区冲突受控，再开放更多入口 |

首个可用版本按 A → B 推进，B 发布所需权限和停止边界同步完成，不推迟到 C。标准 Claude Code 未通过验证前标记待支持，KSCC 的成功不替代其验收。

| 必验场景 | 预期 |
| --- | --- |
| Pi 服务不可用，切到 Codex | 宿主独立准备交接，不依赖 Pi 总结 |
| 工具运行中停止并切换 | 旧回合终止确认后才启动新执行，停止失败有明确状态 |
| 目标启动失败/权限不兼容 | 不丢记录、不静默换模型或扩权，可重试或另选 Agent |
| Pi → Codex → Pi | 补齐中间增量，不把旧 Pi 上下文当成当前完整上下文 |
| 切换准备、待投递、执行期间重开 | 绑定与交接状态一致，不误显示已同步，不自动重复执行 |
| 含图片、工具和长输出的多轮会话 | 不超目标预算、不重复落盘，省略信息可解释 |
| 官方内核升级 | 协议回归和真实账号烟测通过后启用；失败保留可用版本 |

验证分为事件/迁移回归、模拟进程故障、公司账号真实任务三层。自动化通过不等于真实渠道稳定，烟测也不等于长期可靠；发布记录写明验证版本和未覆盖项。

## 10. 本轮范围

首期开发围绕三条现有路径收敛：独立 Agent 选择器、模型按内核过滤、停止后手动切换、绑定与待投递交接资料落盘。不同时建设任意 CLI 插件系统、自动质量判定、自动容灾或完整 DAG 编排。

实施取舍：首版跨内核一律新建原生上下文，归档旧原生 ID；先使用固定字符预算的可见历史摘录。须先手动停止当前回合，再选择目标 Agent。逐条消息内核归属、可展开的交接状态、目标容量自适应预算、完整进程树停止保证和并行工作区写入隔离尚未交付，不以本切片代替阶段 A–D 的全部验收。

实际交付、验证证据与限制见 [首期实施记录](../dev/three-runtime/implementation-status.md)。

衡量首期成果：用户知道谁在工作，能主动换另一个，必要上下文和已有成果能接上；Pi 保留定制能力，外部内核按验证过的版本持续更新。
