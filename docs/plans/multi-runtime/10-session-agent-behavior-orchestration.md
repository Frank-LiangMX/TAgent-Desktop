# 10 — 会话内 Agent 行为编排（说 / 议 / 干）

> 所属：[multi-runtime](./README.md)
> 关联：ADR-0004、01（名词表与真值模型）、02（Chat/Work 双轴）、03（机制边界）、05（MoA/kscc）、06（UX 可见性）
> 状态：设计定稿 · 阶段 1/2 已实现（阶段 3/4 待做）
> 目的：把 **普通对话 / @ / 圆桌 · 快速 / 圆桌 · 研讨 / 子代理 / 看板班组** 的功能、入口、边界、UI 统一理顺，成为会话内一切 Agent 行为的编排依据。

> **范围更新（2026-08-11）**：本文只约束普通会话内的行为机制。用户 + 多个独立 Agent 的持久聊天、并行执行与 A2A，采用独立 Rail 入口的 [Agent 协作室](../agent-collaboration-room/00-MASTER.md)，不作为本文发送菜单中的新模式。

## 1. 背景与问题

功能先于设计长出。各机制目前入口割裂：

| 机制 | 现状入口 | 问题 |
| --- | --- | --- |
| 普通对话 | 主发送键 | 无 |
| @ | 输入框打 @ + MentionPicker | 与其它机制无统一心智 |
| 圆桌 · 快速（原会诊） | ModelSelector「会诊·MoA」分组（sticky）+ 发送旁 ▾（one-shot） | 动作伪装成模型；两处入口 |
| 圆桌 · 研讨（原圆桌讨论） | 发送旁 ▾（one-shot） | 未实现 → 阶段 2 已实现 |
| 子代理 | 模型自主触发（task tool） | 用户无入口、无统一编排 |
| 看板/班组 | Work 右栏 / Dockview pane | 信息架构未撑起 worker 会话与嵌套 |

由此产生两类症状（均有审计实证）：

- **误触发**：普通轮被拉去会诊（`AUDIT-latest-session-FINDINGS.md` turn 8/9）。
- **绕过机制**：用户显式要求会诊时，主 agent 用通用 Agent 工具手搓 3 席（同审计 turn 10）。

根因：用户发送前不知道本条消息会触发什么，模型也没有被约束成按统一决策表选机制。

## 2. 心智模型：说 / 议 / 干

```
说（Talk）：普通对话 · @ 点名        —— 对齐想法，不产生任何"活"
议（Deliberate）：圆桌 · 快速 · 圆桌 · 研讨 —— 多模型把想法变扎实，不碰文件
干（Do）：子代理 · 看板班组           —— 把主意变成现实，才允许动文件/派任务
```

组合路径是一条显式流水线：

```
说 → 议 →（用户确认）→ 干 → 结果回流 → 说
```

## 3. 机制总表

| 机制 | 一句话 | 入口 | 生命周期 | 结果 | 下一步 | 关键边界 |
| --- | --- | --- | --- | --- | --- | --- |
| 普通对话 | 主模型回答 | ↑ 主发送键 | 一轮问答 | 气泡 | 继续聊 | 无 |
| @ | 点名角色卡发言，用户在场 | 输入框 `@` | 单轮/跟随（followMode） | 铭牌气泡 | 插话/切回总助 | 仅 Chat；不产生工单 |
| 圆桌 · 快速 | 多模型并行交卷 → 汇总 | ▾ 选圆桌 · 快速 | pending→running→ok/failed→汇总 | 圆桌卡 + 汇总结论 | 追问某席/再会诊/照着干 | 席位无工具；rounds=1 |
| 圆桌 · 研讨 | 多模型互相对话 → 共识方案 | ▾ 选圆桌 · 研讨 | 多轮讨论 + 共享纪要 → 收敛/到轮限 → 总结人收口 | 讨论室 + 共识方案 | 追问观点/换阵容/照着干 | 轮数可配 1–6（默认 3）；用户可插话/喊停；席位无工具 |
| 子代理 | 短命委派，办完回传 | 模型自主（Work 可写） | 入口卡 → 全屏详情页 | 结果折叠卡 | 查看/复制/升级看板 | Chat 只读；深度 1；不建板 |
| 看板/班组 | 长任务容器 + 工人会话 | Work 右栏 / 照着干 CTA | pending→ready→running→done/failed/blocked | 任务结果回流 | 验收/重试/解除阻塞 | 仅 Work；worker 不建板 |

## 4. 入口设计（统一本轮动作）

原则：**「用谁说话」与「本条消息怎么处理」分开。**

### 4.1 输入框

```
[ 模型选择器（只选真实模型） ]  [ 输入框（可 @ 选人） ]  [ ↑ ] [ ▾ ]
```

- ↑ 主发送键：普通发送，当前模型回答。
- ▾ 本轮动作菜单（按 executionMode 收敛）：
  - Chat：会诊 / 圆桌讨论
  - Work：会诊 / 圆桌讨论 / 派工
- @ 留在输入框内（主流 IM 习惯，不改）。
- 模型选择器回归真实模型；**sticky 会诊已移出 ModelSelector**（现状代码已完成：选择器不再提供预置；旧会话残留 `moa:*` 自动落回渠道默认真实模型，见 `Chat.tsx` L648 迁移逻辑）。
- **主入口 = 会诊本条（one-shot）**，对齐 `02-SESSION-UX-SPEC` 定案；「持续会诊」开关列为后续可选项（引入 sticky 状态需另行评估收益，非本次理顺范围）。

### 4.2 ▾ 菜单文案（让用户秒懂）

- 圆桌 · 快速：各答各的 → 汇总
- 圆桌 · 研讨：互相讨论 → 共识方案
- 派工（Work）：拆任务交给工人执行

### 4.3 模式开关

Chat / Work 全局开关保留。切换规则沿用 02：**只有用户能改**；AI 只能弹建议条。

## 5. 圆桌双模式

MoA 是总称，下面两个模式。两者都是「议」，都不碰文件。

### 5.1 圆桌 · 快速（原会诊，已实现，保持）

- 并行独立交卷 → 汇总席汇总。
- 席位互不可见、无工具、rounds=1。
- UI：时间线圆桌卡 + 右侧 Sheet 看全文（内容少，不跳页）。

### 5.2 圆桌 · 研讨（原圆桌讨论，已实现）

- 多模型围坐，**互相可见、可引用/反驳**，多轮对话后由**总结人收口**成共识方案，交回主会话。
- 与 @ 的区别：@ 是用户在场的点名聊天；圆桌 · 研讨是模型间对话，用户旁观 + 可插话。
- **运行形态**：每席每轮 = 无状态单发（kscc bare 子进程 / Pi HTTP 直连），串行执行；"多轮对话"由编排层以「议题 + 共享纪要 + 最近发言」重发 prompt 模拟，各席无真会话状态。
- **历史注入（T5）**：讨论开始前把主会话近期历史（`buildMoAHistoryFromMessages`，排除本轮 user）注入议题，模型不是只看到本轮输入。
- **共享纪要（T11，借鉴 Hermes 思想、代码原创）**：每 2 轮用一个隔离纪要模型把「旧纪要 + 新增发言」滚成结构化纪要（当前目标 / 已确认决定 / 未决事项 + 收敛标记），下一轮参与者读「议题 + 纪要 + 最近发言」而非全文堆积——解决后几轮发散。
- **落盘与恢复（T8）**：终态 panel（speakers + entries + summary）落盘 `<sessionId>.moa-discussion.jsonl`，重启/切会话后 `replayMoADiscussions` 推回渲染层，入口卡插到共识消息前，可进讨论室回看。
- UI：主时间线只放**入口卡**（讨论中：谁正在发言；完成：结论摘要）→ 点击进入**全屏讨论室**（主会话质感：席位头像/模型名/markdown/跟随滚动/可折叠纪要区 + 底部输入框插话/喊停）。

### 5.3 用户席（已实现）

- 讨论进行中，讨论室输入框即「向圆桌发言」。
- **插话（T4）**：输入框回车 → `DISCUSSION_INTERJECT` IPC → 编排层下一轮 drain → 落 user entry + 参与者 prompt 追加 `[用户插话]`，模型先回应你再继续。
- **喊停（T4）**：「结束讨论」→ `DISCUSSION_STOP` IPC → abort → 保留已发言、卡标「已取消」。
- 你的发言在讨论记录中有独立样式（右对齐/高亮/「你」标识）。
- 插话不重置安全边界：仍在「议」内，不碰文件；插话后模型再聊有限轮即收敛。

### 5.4 防失控

- 轮数上限（默认全场 ≤3 轮，可配：班底 `roundLimit`，1–6 整数，缺省 3，T10），到点必须收口。
- 提前收敛（T9）：聊满 ≥2 轮后，若本轮参与者发言普遍过短或多数已表态同意，即提前收口。
- 纪要收敛升级（T11）：纪要模型输出「收敛: 是」（未决事项为空且目标已覆盖）→ 直接进入收口；T9 作为纪要失效时的降级。
- 必须有总结人（moderator），负责把讨论收敛成方案，不得再开一场讨论。
- 参考/讨论席无工具（与圆桌 · 快速一致）。
- 议 → 干必须用户确认（照着干 → Chat/Work 确认条 → 建板）。

## 6. 边界总则

1. 说和议不碰文件，干才碰文件。
2. @ 只在 Chat；Work 里想讨论就切回 Chat。
3. 会诊/圆桌讨论席位无工具，只出主意。
4. 从议到干必须用户确认（AI 只能弹建议条）。
5. 从干到议随时可以（切回 Chat，后台任务不杀）。
6. 圆桌讨论必须有轮数上限和总结人，防止无限互聊。
7. 任何「干活」都能被追溯：子代理折叠卡、看板任务、回流通知，都在时间线上有迹可循。

## 7. UI 骨架

### 7.1 统一导航模式：入口卡 → 全屏详情页

复用子代理已趟出的模式（`SubagentEntryCard` → `SubagentDetailView`）：

```
主时间线/工作区（只放入口） → 点击 → 全屏详情页（顶部「返回」）
```

所有"重内容"共用这一种导航习惯：

| 内容 | 入口形态 | 全屏页 |
| --- | --- | --- |
| 子代理 | 折叠卡（状态/进度） | 子代理详情页（现状，只读回放） |
| 圆桌 · 研讨 | 入口卡（谁在发言/结论摘要） | 讨论室（主会话质感：头像/markdown/纪要区/插话/喊停） |
| worker 会话 | 班组任务上的入口 | worker 会话页（真会话回放） |

会诊是例外：内容少，留在时间线（卡 + Sheet），不跳页。

### 7.2 时间线类型标签

所有非普通消息带类型标签，翻记录不迷路：

| 消息 | 形态 | 标签 |
| --- | --- | --- |
| 普通 | 气泡 | — |
| @ 发言 | 铭牌气泡（角色名+模型） | @角色 |
| 圆桌 · 快速 | 圆桌卡 | 圆桌 · 快速 |
| 圆桌 · 研讨 | 入口卡 | 圆桌 · 研讨 |
| 子代理 | 折叠卡 | 子代理 |
| 看板回流 | 通知卡 | 看板 |

### 7.3 班组：重容器，轻打扰

**重的是能力，轻的是打扰。**

重（信息架构）：

```
班组工作区（board 视图：flow 依赖图 + 任务列表 + 详情）
   ↓ 点任务/worker
worker 全屏会话页（复用 SubagentDetailView 模式：完整对话 + 工具调用 + 返回）
   ↓ 点 worker 开的 subagent
subagent 全屏详情页（复用现有模式）
```

- 依赖用 flow 可视化（现状为文本列表，需升级）。
- worker 是真会话（`assigneeSessionId`），需独立全屏会话页（现状为内嵌文本 transcript，需升级）。
- worker 的 subagent 需要入口（现状无）。

轻（默认存在感）：

- 无板时不渲染（现状 `KanbanCrewPanel` 已做到）。
- 首次有进行中的板自动开一次，用户关闭后不再强制开（现状已做到）。
- 右栏可拖宽；可拖成 Dockview pane（用户主动，不算打扰）。

现状 `KanbanCrewPanel` 骨架保留，升级三件事：**flow 可视化、worker 真会话页、嵌套 subagent 入口**。

## 8. 组合路径

**升级（鼓励）**：

- @ 讨论对齐 → 卡上「以共识开会诊」CTA（前文打包成议题）。
- 会诊/圆桌讨论 done → 「追问某席 / 换班底再议 / 照着干」（照着干 = 切 Work 确认条 + 建板）。
- SubAgent 反复失败 → 建议升级看板任务。
- worker 完成 → 回流通知（现状 `kanban-reflux` 已有）。

**降级**：

- 误建板的小事 → 取消/合并，改 SubAgent。
- 只需聊天 → 切 Chat，勿硬派工。
