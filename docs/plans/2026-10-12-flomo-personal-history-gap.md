## 结论与优先级

TAgent 已有无标题记录、草稿、标签/项目/日期筛选、置顶归档回收站、Agent 整理回写、来源笔记关联、手动入知识库、周/月排期和工作日报。当前主要缺口是长期回看、笔记连接和持续知识积累。

结合用户新增的「时间久后如何知道哪天做了什么」，优先顺序建议为：

1. 可靠留存个人活动历史，提供按日的完整足迹。
2. 改善收集入口、标签与来源管理，增加旧笔记回顾。
3. 相关笔记、引用与多条资料合并为主题知识。
4. 主题地图与可核对的个人记忆档案。

保留现有四个主入口，不为每项能力增加一级模块：今天负责记录和安排，收集负责资料与知识连接，日程负责计划，回顾负责历史与复盘。

## 用户追加的硬要求：整理产物必有标签

所有保存的 Agent 整理产物必须有可编辑标签，不能默认空数组：随笔整理、链接摘要、文档提炼、日报/周回顾、主题知识，以及从资料整理生成的待办和日程。原始随手记录允许先不分类。

拟议规则：继承适用的来源标签，依据正文补充有意义的主题标签；优先复用已有标签，避免近义词重复和随意增长。标签由 Agent 自动给出，用户可修改；保存整理产物时至少保留一个有效标签，缺失时应补齐或提示，不能只靠提示词承诺。多来源整理不机械拼接全部来源标签，而应选择与结果有关的标签。标签不应只有「AI 整理」「笔记」等无助检索的泛称。

同一标签应贯通收集、知识文档、待办/日程和回顾检索；入知识库保留标签与出处，按日足迹支持标签筛选。层级标签需要实际的父子范围检索和导航，不能仅允许输入斜杠文字。标签变更应保留必要历史，避免重命名后失去旧资料的关联。

当前差距：工作台笔记已有 `tags`，但工具默认允许空标签；工作台待办、日程与日报契约没有标签字段。实现时需要统一补齐数据契约、持久化、Agent 工具和界面，兼容旧记录；原始无标签资料与需要补齐标签的历史整理稿应明确区分，不为所有旧资料随意编造分类。

## 用户新增需求：按日期知道自己做过什么

推荐在现有「回顾」中提供「每日足迹」。按月浏览有记录的日期，点击某一天查看完整时间线；能按项目、类型、关键词搜索，并支持 Agent 根据日期范围提取有来源的回顾。

当天内容应包括：

- 实际完成的工作和个人待办、记录的工作进展与结果。
- 当天发生的随笔/灵感、收集的链接和附件、Agent 整理成果。
- 明确标为计划的日程，以及取消、改期、完成等事实。
- 当天确认保存的知识成果与日报/个人小结。

计划时间不证明活动发生；创建记录的时间不必然等于事情发生时间。补记过去的事，应落到用户选择的发生日期，并保留实际记录时间。没有具体发生时刻的资料按日期展示，不以保存时刻冒充发生时刻。

### 当前数据不能保证历史完整

源码已核对：

- `WorkbenchNote` 有发生日期、创建/修改时间和版本号，但没有历史正文集合。
- `WorkbenchTodo` 只有当前 `completedAt`；重新打开会将其清空，再完成会写新时间，无法还原之前的完成过程。
- 日程起止时间直接编辑；删除会移除实体，不能回看当时安排与后来的更改。
- 知识库入库保存来源笔记 ID/版本备注，但工作台没有统一的入库活动记录或完整反向关系。
- 日报保留来源文字快照，可用于已生成日报的事实核对，但不覆盖所有生活、随笔、计划和操作历史。

因此只给现有状态加日期筛选不足以实现长期回看。

### 建议实现方式

本地业务服务在关键变更成功时，同步保存活动事实与必要快照，例如完成/重新打开待办、调整/取消日程、保存工作进展、产生整理稿、确认入库。保存稳定实体 ID、来源版本、发生时间、记录时间及本地日期语义。

活动事实与当前状态分开：后续编辑或重新打开不抹去旧事实；修正可追加说明，并允许用户显式清理个人历史。不要记录每次输入或把所有编辑当成实际工作成果。跨工作台/知识库的写入需要去重和可靠关联，不能因重试产生多条足迹。

每日足迹直接由已保存事实构成，打开页面不依赖模型。AI 可在其上生成带来源的小结；重新生成保留旧版本，用户编辑和定稿不被覆盖。年度/月度热力图仅反映有记录的活动与数量，不估计没有证据的工时或效率。

旧数据可按现有发生日期、完成时间和日报快照回看；未保存的历史改期/完成操作无法可靠重建，必须说明范围，不能补造。

## 下一版建议验收

1. 完成待办后次日重新打开，前一天足迹仍可看到那次完成，并可看到后来的重新打开。
2. 日程改期或取消后，原日期的历史保留并标明变化，计划不算实际完成。
3. 随笔、链接整理稿、知识成果能从同一天跳转到原始来源；多来源整理不丢出处。
4. 补记内容按发生日期回看；仅知日期时不伪造具体时刻。
5. 按月/年浏览与日期范围检索跨年正确，工作和个人内容可分别筛选。
6. 重启后历史保留，重试不重复，模型不可用仍可查看每日足迹。
7. 每种保存的整理产物都有有效标签，Agent 漏填不能静默落库；用户可修改，同一标签能查到关联的笔记、知识、待办/日程和回顾成果。

## 2026-10-12 本轮落地

- 在原有「回顾」内实现每日足迹，保留四个主入口：月历记录密度、当天时间线、实际记录/计划切换、项目/标签/关键词筛选。
- 关键变更使用独立持久快照。完成后重新打开、日程改期/改标题/取消、笔记后续修改不会覆盖原历史；跨天计划按覆盖日期展示，明确不代表实际执行。
- 升级时保存仍可恢复的旧笔记、完成事实及日报，并标明原有记录；不补造失去的历史。补记日期与记录时间分开，无具体发生时刻不虚构时刻。
- 笔记、待办、日程、日报、知识文档共享标签规范与层级检索；Agent 整理结果缺少标签会被拒绝，知识文档标签可编辑，分享包保留标签。
- 多选资料交给 Agent 整理，保留全部来源；同标签笔记可直接打开，明确为标签匹配。
- 工作台入库记录来源、标签和知识足迹；足迹写入失败后可重试补记，不重复建文档。恢复默认知识库写入，保留部署方显式关闭选项和 Agent 入库确认。
- 尚未实现：全局速记浮窗、笔记附件、标签集中重命名/合并、历史恢复、语义主题地图、自动增补旧知识、跨设备同步。直接从其他知识库入口创建的文档尚未全部归入每日足迹。
