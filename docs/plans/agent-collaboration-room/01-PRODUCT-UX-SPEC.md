# Agent 协作室：产品 UI/UX 规格

> 上位文档：[00-MASTER](./00-MASTER.md)
> 范围：信息架构、页面、交互、状态和可访问性；不定义底层协议。
> 时间线 / mention / run 卡的落地细节：[04 Hermes 机制移植](./04-HERMES-BORROW-SPEC.md) §4、§8。

## 1. 导航与命名

### 1.1 一级入口

Rail 顺序：

```text
会话
协作   ← 新增，建议使用 Network / CirclesThreePlus 类图标
插件
记忆
角色库
———
设置
```

- Rail 短标签用 **“协作”**，页面产品名用 **“Agent 协作室”**。
- “数字员工”可用于空状态说明或模板名称，不作为核心信息架构名；它容易让用户误解为人事系统或全自动员工。
- “角色库”已有 `UsersThree`，协作入口不得复用同一图标；图标按钮继续使用 tooltip、`aria-label` 和当前项高亮。
- 再点当前“协作”Rail 项，切换协作室侧栏展开/收起；从别页切回时恢复上次房间和侧栏状态。

### 1.2 与普通会话的跳转

- 普通会话提供显式 CTA：“创建协作室处理”或“在协作室中打开”。
- 创建前展示目标、成员和权限确认，不原地改变当前 session 类型。
- 协作室中的单个 run 可“在详情中查看”，但不自动出现在普通会话列表。

## 2. 桌面页面骨架

```text
┌──────┬────────────────┬────────────────────────────────┬──────────────────┐
│ Rail │ 协作室侧栏      │ 房间主时间线                    │ 团队/任务面板      │
│ 52px │ 240–280px       │ min 480px                      │ 300–360px         │
│      │                │                                │                  │
│      │ + 新建协作室    │ 房间标题 / 工作区 / 预算 / 控制  │ 成员              │
│      │ 房间分组与状态   │                                │ 任务              │
│      │                │ 消息与关键事件                  │ 产物              │
│      │                │                                │                  │
│      │                │ 输入框 / @ / 指派 / 附件         │                  │
└──────┴────────────────┴────────────────────────────────┴──────────────────┘
```

布局规则：

- 复用 `AppShell`，但协作室有自己的 `CollaborationRoomSidebar`，不复用 `SessionSidebar` 的数据状态。
- ≥ 1280px 默认三栏；960–1279px 右面板以 Sheet/可折叠栏呈现；< 960px 只保留侧栏或主区之一，右面板为全屏详情。
- 每栏只有一个主要滚动容器；主时间线虚拟化，避免嵌套滚动。
- 右面板记住用户展开状态；重大阻塞可自动显示提示，但不强制展开面板。

## 3. 协作室侧栏

房间列表按工作区分组，单项展示：

- 房间名。
- `运行中 / 等待你 / 已阻塞 / 已暂停 / 空闲` 文本状态和对应图标。
- 未读数字；仅用颜色表达状态是不合格的。
- 最后活动时间和最多两个活跃成员头像。

顶部操作：

- “新建协作室”主按钮。
- 搜索/筛选：全部、运行中、等待我、已归档。
- 无工作区时，引导先打开项目目录。

房间右键/更多菜单：重命名、暂停/恢复、复制配置、导出记录、归档。删除属于二阶段；若提供，必须解释任务/产物是否保留并二次确认。

## 4. 房间头部

始终可见的信息：

- 房间名与总状态。
- 绑定工作区；点击可在文件管理器打开。
- 当前运行数/并发上限。
- 用量摘要（已用/上限；无法获得 token 时至少显示 turn 和运行时长）。
- “暂停新运行”“停止全部”“设置”操作。

危险操作区分：

- **暂停**：不再启动新 run；已运行 turn 可完成。
- **停止全部**：取消当前 run，未处理信箱保留并标记取消原因。
- **归档**：停止调度并从活跃列表移除；消息和产物保留。

## 5. 主时间线

### 5.1 默认展示什么

默认“安静时间线”只展示：

- 用户消息。
- 成员对用户或房间公开的发言。
- A2A 的可读摘要，例如“前端向架构师询问接口契约”。
- 任务创建、阻塞、完成和失败。
- 权限等待、预算阈值、文件冲突等需要用户理解的事件。
- 协调者最终汇总。

默认折叠：token delta、内部 prompt、每条工具调用、心跳、重复重试、模型原始协议事件。点击 run 卡进入详情查看。

进行中的成员不要再画成与用户气泡同级的灰色「思考中」行。按 `runId` 使用一张 in-progress 卡；头部保留 `运行 x/y`。排序与聚合见 [04 §8](./04-HERMES-BORROW-SPEC.md)。

### 5.2 消息与事件类型

| 类型 | 主视觉 | 必备元信息 |
| --- | --- | --- |
| 用户消息 | 现有用户气泡 | 时间、附件、目标成员 |
| Agent 发言 | 头像 + 名称 + 岗位 + Markdown | 模型/CLI、run 状态、回复对象 |
| A2A 请求/回复 | 成对事件卡，可展开原文 | from/to、requestId、因果链 |
| 任务事件 | 紧凑状态卡 | taskId、负责人、状态、看板链接 |
| 产物 | 文件/差异卡 | 路径、作者、对应 task/run |
| 系统警告 | 高对比横幅 | 原因、影响、恢复操作 |

Agent 发言右上角菜单：回复、引用、查看运行详情、复制、定位对应任务。用户不能编辑已触发执行的历史消息；可发送更正或取消其下游运行。

### 5.3 跟随与未读

- 用户停留在底部时自动跟随；向上阅读后停止抢滚动，并显示“回到最新（N）”。
- 连续 delta 在 100–200ms 合并渲染，避免布局抖动。
- 切房间不丢流；全局 listener 维护运行状态和未读计数。
- Agent 名称、状态和目标使用文本/图标，不只用颜色。

## 6. 输入与路由

输入框复用现有附件、Markdown 和 MentionPicker 的视觉与键盘习惯，但语义不同：

| 用户操作 | 默认路由 |
| --- | --- |
| 直接发送 | 协调者 |
| `@成员` | 仅目标成员 |
| 同时 `@A @B` | 两成员并行收到同一根消息 |
| 回复某条 Agent 消息 | 该成员，携带 replyTo |
| `@all` | 仅用户可用，发送前显示预计目标和成本。协调者作为 Agent 不能靠文本升级成广播 |
| “指派任务” | 打开结构化任务表单，不靠自由文本猜状态机 |

输入框附近提供三个低噪声动作：

- `@` 点名（chip 携带稳定 `memberId`；手打未选中时才按 displayName 兜底，见 [04 §4](./04-HERMES-BORROW-SPEC.md)）。
- “指派”按钮：标题、负责人、依赖、验收标准、是否挂看板。
- 附件。

当目标 Agent 离线或不具备所需工具时，发送前提示“将排队”或“此成员只读”，并给出更换目标的恢复路径。

## 7. 右侧团队/任务面板

建议三个 Tab：**成员 / 任务 / 产物**。

### 7.1 成员

每个成员卡显示：

- 头像、名称、岗位、模型/CLI。
- `空闲 / 排队 / 执行中 / 等待同伴 / 等待你 / 阻塞 / 完成 / 失败 / 暂停 / 离线`。
- 当前任务或最近活动、耗时、用量。
- 操作：点名、暂停、取消当前 run、查看详情。

成员详情是独立全屏/Sheet，复用 `SubagentDetailView` 的导航心智，展示成员摘要、信箱、run 列表、工具过程、权限和输出，不把所有噪声塞回房间时间线。

### 7.2 任务

- 无看板：显示轻量 room task 列表，支持负责人、依赖和状态。
- 已挂看板：显示看板摘要和跳转入口；不在房间复制一套可漂移的状态。
- 房间消息和任务通过 `taskId` 双向定位。

### 7.3 产物

- 按任务聚合文件、diff、报告和外部链接。
- 显示作者成员、产生 run、最近更新时间和冲突状态。
- 打开文件沿用工作区鉴权预览；不得从消息中的任意路径直接读取系统文件。

## 8. 创建协作室流程

采用分步 Sheet 或全页向导，默认值足够好，避免一次显示所有高级项。

1. **目标与工作区**：房间名、目标、项目目录。
2. **团队**：选择 1 个协调者、1–6 个成员；为每人选择角色和模型/CLI。
3. **执行边界**：只读/可写、工作树策略、并发、时间/用量上限。
4. **确认**：成员与预计成本、权限摘要；创建后才启动运行。

快捷模板可以后置。首版只需“软件开发小组”和“空白团队”，模板最终仍落成同一套可编辑配置。

## 9. 空、错、等、停状态

| 状态 | 页面必须回答 |
| --- | --- |
| 空房间 | 下一步是什么？提供示例目标和 `@成员` 教程 |
| 正在运行 | 谁在做什么？是否能暂停/查看详情？ |
| 等待同伴 | 谁问了谁？等待多久？可否转给别人或取消？ |
| 等待用户 | 需要用户做哪个决定？选项和影响是什么？ |
| 失败 | 哪个 run 失败？已产生哪些副作用？可重试/换模型/跳过吗？ |
| 文件冲突 | 哪些成员、哪些文件、当前租约？可串行、隔离或人工解决吗？ |
| 超预算 | 已用多少？暂停了什么？增加预算或结束房间的区别是什么？ |
| 离线 CLI | 哪个二进制不可用？重试探测、换后端或停用成员 |

错误必须带恢复动作，不能只 toast 一句后消失。

## 10. 动效、性能与可访问性

- 沿用语义色和 4/8px 间距体系；不为协作室另造一套视觉语言。
- 动效 150–300ms，只使用 `transform/opacity`；遵循 `prefers-reduced-motion`。
- 所有可点击图标有 tooltip 与 `aria-label`；焦点环清晰，键盘可遍历 Rail、房间列表、消息操作和 Tab。
- 文本对比度至少 4.5:1；运行状态同时使用图标、文字和颜色。
- 长时间线、run 列表和产物列表做虚拟化；房间切换时避免重放全部 delta。
- 破坏性操作使用明确动词，不用模糊“确定”；暂停与停止不能混为一个按钮。

## 11. 前端组件建议

新增：

```text
renderer/features/collaboration/
  CollaborationRoomsPage.tsx
  CollaborationRoomSidebar.tsx
  CollaborationRoomHeader.tsx
  CollaborationTimeline.tsx
  CollaborationComposer.tsx
  RoomRosterPanel.tsx
  RoomTasksPanel.tsx
  RoomArtifactsPanel.tsx
  CreateRoomFlow.tsx
  MemberDetailView.tsx
  RunDetailView.tsx
  atoms/
  hooks/
```

优先抽取/复用：

- 现有 Markdown、附件预览、消息复制、跟随滚动、权限卡、工具过程卡。
- `SubagentEntryCard → SubagentDetailView` 的入口卡/详情页模式。
- AppShell 侧栏机制、全局状态 ticker、工作区选择器、角色/模型选择器。

不得直接复用：

- `SessionSidebar` 的 session 列表和选择状态。
- `Chat.tsx` 的单 session 编排状态。
- 普通 `@` 的角色投影逻辑。
