## 1. 背景与讨论脉络（需求如何演进）

1. 起点：用户觉得会话里的 看板 / 子代理 / 会诊 / @ 各种 agent 行为入口割裂、边界混乱，需要整体编排。
2. 定稿设计：**说 / 议 / 干** 心智模型 + 四机制边界 + 输入框统一入口（见 10 号文档 §2–§4）。
3. 关键拍板（用户确认）：
   - MoA 是总称，两个模式：会诊（并行交卷，已开发）与**圆桌讨论（模型间互相对话，新开发）**。
   - **用户是圆桌的一席**：讨论中可插话、可点名某席先回应、可喊停。
   - 命名不用「会诊」→ 统一为「圆桌 · 快速 / 圆桌 · 研讨」。
   - 圆桌讨论页面像主会话：头像、模型名、markdown、跟随滚动。
   - 默认 3 轮 + **提前收敛**（用户实测后几轮发散）。
   - 参考 Hermes Studio 的做法（共享纪要/停止机制），**只借鉴思想，代码与提示词原创，不照抄**。
4. 用户实测反馈驱动的迭代：
   - 「后几轮不知道在讨论什么」→ T9 提前收敛 + T11 共享纪要。
   - 「重启入口就没了」→ T8 终态落盘 + 重启回放。
   - 「好像没有上下文记忆」→ T5 历史注入 + T7 跨轮续聊修复。

## 2. 设计成果（详细见 10 号文档）

- **心智模型**：说（普通对话 / @）· 议（圆桌 · 快速 / 圆桌 · 研讨）· 干（子代理 / 看板班组）。
- **入口**：模型选择器只选真实模型；发送旁 ▾ = 本轮动作（普通 / 圆桌 · 快速 / 圆桌 · 研讨 / Work 派工）；@ 留在输入框。
- **圆桌 · 快速**：并行独立交卷 → 汇总（保持原会诊行为，只改命名）。
- **圆桌 · 研讨**：多轮互相对话 → 总结人收口；用户旁观 + 可插话/喊停。
- **UI 骨架**：入口卡 → 全屏详情页的统一导航；班组 = 重容器轻打扰（flow 图 + worker 会话页 + 嵌套 subagent，阶段 3 未做）。

## 4. 关键架构决策（明天续接前必读）

- **无状态单发架构**：圆桌研讨每席每轮 = 一次性调用（kscc bare 子进程 / Pi HTTP 直连），"多轮对话"由编排层以「议题 + 共享纪要 + 最近发言」重发 prompt 模拟；模型无真会话状态。这是轻量取舍，后续若要真会话需大改。
- **记录员纪要（借鉴 Hermes 思想，代码/提示词原创）**：每 2 轮用 `preset.aggregatorModelId` 跑纪要（无工具、30s 超时、失败降级不阻断）；旧纪要当基线、新发言当增量；下一轮参与者只读纪要而非全文堆积。
- **收敛双保险**：纪要输出「收敛: 是」（未决事项为空）优先；T9 规则（短发言/信号词）作纪要失效降级。
- **落盘仅终态**：中间发言不逐条落盘，终态 panel（speakers+entries+summary）一行一 JSON；重启经 `replayMoADiscussions` 恢复入口卡。
- **one-shot 语义**：圆桌不写 sticky `moa:*`，选择器保持真实模型；轮数走班底 `roundLimit`。
- **T7 三态**：进程活 → 只前置结论（不重复普通轮）；无进程/重启 → 有 MoA 痕迹则忽略 resume 走面板全量注入（无双上下文）；无 MoA → 现状不变。
- **命名内部约定**：用户可见名「圆桌 · 快速 / 圆桌 · 研讨」；内部标识符仍 `moa_roundtable` / `moa_discussion` / `moa-agg-*` / `moa-disc-agg-*`，**不要改内部名**。

## 7. 手测清单（明天第一件事，按序）

1. 启动应用，设置 → Agent 行为：确认班底编辑器有「研讨轮数」（1–6，留空默认 3），配一个 2 轮的班底。
2. 发一条**圆桌 · 快速**（回归：命名变了、行为不变）。
3. 发一条**圆桌 · 研讨**：看入口卡 → 进讨论室（头像/markdown/滚动/纪要区）→ 中途插话（模型应先回应你）→ 观察纪要是否每 2 轮更新、是否提前收敛收口。
4. 「结束讨论」→ 卡标已取消、发言保留。
5. 跑完一场 → **重启应用** → 打开会话：入口卡还在，点进能回看完整讨论与共识。
6. 圆桌后**追问一句**：确认续聊能引用上一轮圆桌结论（T7 生效）。
7. 有问题先记下来，回来按「先纪要 → 后代码」的方式修。
