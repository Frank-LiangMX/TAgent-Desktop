# 知识库设计决策（当前生效）

首次定稿：2026-08-28  
状态：当前产品与开发的最高优先级约束

## 一句话定义

知识库不是 Office/WPS 阅读器，也不是原始文件网盘，而是一个由 Agent 将外部资料整理成结构化知识、供 Agent 快速检索和引用的长期知识层。

## 核心原则

1. 外部文档是输入材料，不是知识库最终形态。
2. 外部资料必须经过解析、整理、结构化和用户确认，才能成为正式知识。
3. 原始文件不要求高保真还原，也不作为知识库主内容展示。
4. Agent 检索面向结构化知识片段，不要求逐篇翻阅完整文档。
5. 原始来源只保留为追溯信息和失败回退，不参与主要 UI 展示。
6. Agent 不得未经用户确认写入正式知识库。

## 统一工作流

```text
聊天附件 / 本地文件 / 云文档链接 / 粘贴文本
                    ↓
              Agent 读取与解析
                    ↓
        提取事实、规则、步骤、表格、代码和例外
                    ↓
        生成符合知识类型规范的结构化知识草稿
                    ↓
              用户预览并确认
                    ↓
          写入知识库，切分并建立检索索引
```

## 内容分层

### 1. 对话材料

用户在聊天中上传的附件或粘贴的资料，默认只服务于当前任务，不自动进入知识库。

### 2. 来源材料

用户明确导入的本地文件、云文档链接或网页资料。系统保留来源名称、链接、文件类型、抓取时间和位置标记即可，不追求还原原始排版。

### 3. 正式知识

Agent 或用户整理后的结构化内容。正式知识必须经过确认，才能被 Agent 作为可靠知识检索和引用。

## 统一知识文档结构

所有知识文档使用统一元数据，正文按知识类型选择模板：

```text
title       标题
kind        note / norm / contract / guide / reference / snapshot
summary     一句话摘要
content     结构化正文
source      来源文件、链接、页码、工作表或章节
author      user / agent
status      draft / confirmed / archived
updatedAt   更新时间
```

正文不要求所有文档使用同一套字段，但应优先表达：

- 事实和结论
- 适用范围
- 必须做什么
- 禁止做什么
- 操作步骤
- 示例
- 例外和风险
- 来源位置

## Agent 行为

- 收到外部资料后，先读取和整理，不自动保存。
- 用户明确要求“整理成知识库”时，生成结构化草稿。
- 草稿必须展示来源和不确定内容。
- 只有用户确认后才调用受控写入。
- Agent 应通过知识片段检索，不默认读取整篇原始文档。
- 资料解析失败时，报告失败原因，不伪造结构化结果。

## UI 取舍

知识库页面只负责：搜索、浏览、筛选、查看知识、编辑、确认来源和删除。

聊天页面负责：提交资料、启动整理、预览草稿、确认保存。

云文档浏览器、Office 高保真预览、原始文件下载都属于辅助能力，不得成为知识库主流程或主视觉。

## 明确不做

- 不把知识库做成 WPS/Office 的替代品。
- 不强求 DOCX/PDF/XLSX 原样还原。
- 不把每个外部文档直接作为一篇正式知识文档。
- 不让 Agent 静默写入或自动改写正式知识。
- 不要求 Agent 每次从头阅读完整文档。
- 不以项目路径作为知识库存在的前提。

## 当前开发优先级

1. ✅ 聊天附件进入 Agent 的读取链路（`kb_read_attachment`：DOCX/PDF/XLSX/MD/TXT/CSV，会话隔离、零写入）。
2. ✅ 外部资料解析为统一结构化中间格式（文本 / 各工作表）。
3. 👉 **下一步：Agent 生成结构化草稿，用户确认后保存为正式知识（`kb_propose_save`）。**
4. 知识片段切分、全文/关键词索引和来源定位。
5. Agent 检索返回片段、标题和来源位置。
6. 最后再补充云文档和复杂格式适配。
