# 知识库 Agent 模式设计

日期：2026-08-25
状态：Phase 1 实施中

## 结论

知识库不应全局强制 Agent 使用。强制规则只在用户为当前会话选择了知识库模式后生效，并且默认强制的是“先检索”，不是“答案只能来自知识库”。

## 三种会话模式

| 模式 | 是否需要先检索 | 答案来源 | 适用场景 |
| --- | --- | --- | --- |
| 不使用 | 否 | Agent 常规能力 | 普通聊天、写作、开放问题 |
| 优先使用 | 是，至少尝试一次 | 知识库优先，可补充通用知识 | 日常工作、产品文档、项目资料 |
| 仅使用 | 是 | 仅允许知识库；无命中必须说明 | 制度、合规、内部规范、受控问答 |

## 交互原则

1. 知识范围是会话级设置，可以跨轮次保持，不要求用户每次输入“请查知识库”。
2. 用户未选择知识库时，Agent 不应偷偷扫描全盘或自动使用任意知识库。
3. “优先使用”模式下，Agent 必须先调用知识库检索工具；检索不到时可以回答，但要明确区分知识库内容与通用补充。
4. “仅使用”模式下，检索不到足够依据时应直接说明“知识库中没有找到依据”，不得用模型常识伪装成内部结论。
5. 命中知识库后，回答应展示来源文档，至少包含文档名或相对路径；后续可升级为可点击引用卡片。
6. 阅读和检索不会自动写入知识库。保存、整理、更新仍需要用户明确触发。

## Agent 运行契约

知识范围模式写入会话元数据，并随 Agent 系统提示词和工具配置传入运行时：

- `off`：提供工具但不要求调用，当前会话不绑定知识范围时工具返回空结果。
- `preferred`：系统提示词要求回答前先调用 `kb_search`；允许在结果不足时使用通用能力，并标注补充内容。
- `strict`：系统提示词要求只依据检索结果回答；没有足够命中时不得猜测或补充外部结论。

工具仍然是只读的。知识库与记忆层隔离，检索结果不得自动写入记忆或知识库。

## 实施顺序

### P0

- 为会话增加 `knowledgeBaseMode`，默认 `off`。
- 在知识库选择器中提供“不使用 / 优先使用 / 仅使用”。
- 将模式注入 Pi 和 kscc 的系统提示词，并让模式变化触发 Agent 配置重建。
- 绑定知识库时显示当前模式；未绑定时不能进入“优先使用”和“仅使用”。

### P1

- 解析工具结果中的来源，渲染引用卡片。
- 增加“保存为知识文档”和“整理后更新”动作。
- 增加云端 Wiki / WPS 等外部知识源适配器，复用同一套模式契约。

## 验收标准

- 普通会话不因知识库功能改变回答路径。
- 选择“优先使用”后，Agent 每轮回答前确实尝试检索绑定知识库。
- 选择“仅使用”且无命中时，Agent 不编造知识库结论。
- 切换模式或知识库后，后续轮次使用新配置，不需要重启应用。
- 解除知识库选择后，系统提示词不再要求知识库检索。
