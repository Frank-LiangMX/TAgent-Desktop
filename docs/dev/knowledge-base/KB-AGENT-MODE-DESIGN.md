# 知识库 Agent 模式设计

首次定稿：2026-08-25
重构日期：2026-08-28
状态：与 [KB-DESIGN-DECISION.md](./KB-DESIGN-DECISION.md) 对齐

## 1. 目标

Agent 使用知识库的目标是快速找到可信的知识片段，而不是逐篇翻阅 Office、PDF 或网页原文。

知识库不全局强制启用。用户可以在会话中选择知识范围；资料整理则从聊天附件开始。

## 2. 三种会话模式

| 模式 | 检索要求 | 答案来源 | 适用场景 |
| --- | --- | --- | --- |
| 不使用 | 不检索 | Agent 常规能力 | 普通聊天、开放问题 |
| 优先使用 | 回答前先检索 | 知识库优先，可补充通用知识 | 日常工作、产品资料 |
| 仅使用 | 回答前必须检索 | 只能依据知识库 | 制度、规范、受控问答 |

模式是会话级设置，不要求用户每次重复说明。

## 3. 资料整理模式

当用户上传附件或提供外部资料时：

1. Agent 用 `kb_read_attachment(localPath)` 读取并解析资料，识别文档类型（DOCX/PDF/XLSX/MD/TXT/CSV）。附件默认只属于当前会话，工具只读当前会话目录、不自动保存。
2. 提取事实、规则、步骤、表格、代码、例外和来源位置。
3. 按对应知识类型生成结构化草稿。
4. 向用户展示草稿、来源和不确定内容。
5. 用户确认后，调用 `kb_propose_save` 写入正式知识。
6. 写入后再切分索引，供后续检索。

附件默认只是当前对话材料。用户说“总结一下”不等于授权保存；只有明确要求整理入库并确认后，才产生正式知识。

## 4. 检索规则

- `kb_search` 优先返回知识片段、章节和来源位置。
- `kb_get` 只在需要全文或核对上下文时使用。
- 正式知识优先于未确认草稿。
- 用户确认的知识优先于 Agent 自动整理内容。
- 资料冲突时展示多个来源，不自行覆盖。
- 检索结果不足时，Agent 必须说明依据不足。

## 5. Agent 工具

当前工具：

- `kb_list_roots`：列出当前会话绑定的知识库和来源。
- `kb_search`：在授权知识范围内检索。
- `kb_get`：读取命中的正式知识或授权来源文件。
- `kb_list_available`：未挂库时仅发现库的元数据，不返回正文。
- `kb_read_attachment`：读取并解析当前会话刚上传的附件（.docx/.pdf/.xlsx/.md/.txt/.csv），返回结构化文本或各工作表内容，供整理成草稿；只读当前会话附件目录、会话隔离、不写入知识库、不自动保存。
- `kb_propose_save`：提议创建正式知识，必须经过用户确认。

后续工具：

- `kb_propose_update`：对已有知识提出修改，展示差异后确认。
- `kb_reprocess`：重新解析来源材料并生成新草稿。

禁止提供绕过确认的静默写入工具。

## 6. 权限和边界

- 未绑定知识库时，不读取任意知识库正文。
- 不扫描全盘寻找可能相关的库。
- 不把知识库内容写入记忆系统。
- 不把聊天附件自动转成正式知识。
- 不得声称“已保存”，除非工具返回 `ok:true`。
- 外部来源只能作为 Agent 的输入，不得通过来源页面权限绕过用户登录。

## 7. 引用

Agent 使用知识库回答时，回答应展示：

- 知识文档标题；
- 相关章节或片段；
- 来源文件、链接、页码或工作表；
- 必要时给出可点击的来源芯片。

引用来自工具结果，不依赖模型手写的 `[KB: ...]` 文案。

## 8. 已完成与缺口

### 已完成

- 会话级知识库选择和三种模式；
- Pi 与 kscc 双 Agent 工具挂载；
- 正式文档搜索和引用；
- 受控保存确认；
- 基础附件保存和本地资料入口；
- 聊天附件 Agent 读取与解析（`kb_read_attachment`：DOCX/PDF/XLSX/MD/TXT/CSV 统一中间格式，会话隔离、防路径穿越、零写入、不自动保存）。

### 当前缺口

- 附件已能被 Agent 读取与解析，下一步仍是「生成结构化草稿 → 用户确认 → `kb_propose_save` 保存」这一段尚未打通（草稿生成、来源展示与确认 UI 仍需建设）；
- `kb_search` 仍以文档/关键词命中为主，尚未完成知识片段索引；
- DOCX/PDF/XLSX 解析已有统一中间格式，但表格/复杂版式的结构化抽取仍可加强；
- 已有文档的差异更新工具尚未实现；
- 三种模式仍需真实 Agent 端到端验收。

## 9. 开发顺序

1. ✅ 聊天附件进入 Agent 读取链路（`kb_read_attachment`）。
2. ✅ 统一解析中间格式（DOCX/PDF/XLSX/MD/TXT/CSV → 文本 / 工作表）。
3. 👉 **下一步：生成结构化知识草稿，展示来源与不确定内容，用户确认后用 `kb_propose_save` 保存为正式知识。**
4. 按标题和语义边界切分知识片段。
5. 建立全文/关键词索引。
6. 返回片段和来源位置。
7. 再做向量检索、重新处理和版本链。

## 10. 验收标准

- 用户上传文档后，Agent 能先整理而不是要求用户手动进入知识库。
- Agent 不会因收到附件而静默写库。
- 确认保存后，知识可以被片段级检索。
- 回答能显示真实来源位置。
- 未挂库和仅使用模式仍遵守权限边界。
