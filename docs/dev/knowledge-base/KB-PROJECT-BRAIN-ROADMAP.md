# 知识库开发路线图（结构化知识方向）

首次定稿：2026-08-27  
重构日期：2026-08-28  
状态：当前开发顺序

> 详细产品决策见 [KB-DESIGN-DECISION.md](./KB-DESIGN-DECISION.md)，产品约束见 [KB-PRODUCT-SPEC-v2.md](./KB-PRODUCT-SPEC-v2.md)。

## 1. 产品目标

知识库的目标不是保存漂亮的 Office 文档，而是让 Agent 在大量资料中快速找到可信、可引用的知识片段。

主链路：

```text
资料输入 → Agent 解析 → 结构化草稿 → 用户确认 → 分片索引 → Agent 检索
```

## 2. 现状判断

已经完成的工作主要建立了知识库底座：

- 应用级知识库和会话绑定；
- 正式文档 CRUD；
- 基础关键词检索和来源引用；
- Agent 受控保存；
- 本地文档和云文档入口；
- 基础聊天附件保存。

但当前仍存在结构性缺口：

- 聊天附件已能被 Agent 读取与解析（`kb_read_attachment`，DOCX/PDF/XLSX/MD/TXT/CSV 统一中间格式），但「解析 → 结构化草稿 → 用户确认 → 保存」整段尚未打通；外部文档导入也尚未统一进入该链路；
- 正式文档仍以整篇内容为主，缺少知识片段索引；
- WPS/Office 适配投入偏重，容易把产品带向文档管理器；
- Agent 创建知识和用户导入资料的生命周期还没有统一。

## 3. 下一阶段：结构化 ingest MVP

### 目标

让用户不进入知识库页面，也能在聊天中提交资料并得到可确认的知识草稿。

### 工作内容

1. ✅ 附件输入接入 Agent 读取（`kb_read_attachment`，会话隔离、零写入）。
2. ✅ 建立 DOCX/PDF/XLSX/MD/TXT/CSV 的统一解析中间格式（文本 / 各工作表）。
3. ✅ **Agent 草稿链路已接通：** `kb_read_attachment` 输出统一解析结果，`kb_propose_save` 接收摘要、来源、解析提示和不确定项，用户确认后才写入正式知识。仍待真实模型端到端验收。**
4. 网页正文与云文档链接的统一解析（后续辅助能力）。
5. ✅ 正式文档已按标题、段落和代码边界做进程内片段切分，`kb_search` 返回 `chunkId`、章节和行号；持久化 SQLite FTS 仍待完成。

### 验收

- 上传一篇文档即可在聊天中请求整理；
- Agent 能生成结构化草稿；
- 草稿不进入正式检索；
- 用户确认后才成为正式知识；
- 解析失败时能说明原因，不伪造内容。

## 4. 再下一阶段：片段检索 MVP

### 目标

让 Agent 根据问题直接命中相关知识片段，而不是读取整篇文档。

### 工作内容

1. 按标题和语义边界切分正式知识；
2. 为每个片段保存文档、章节和来源位置；
3. 建立 SQLite FTS/关键词索引；
4. `kb_search` 返回片段、摘要、章节和来源；
5. `kb_get` 只在需要时返回全文；
6. 回答展示来源芯片。

### 验收

- 大文档问题能返回少量相关片段；
- 多工作表能定位到具体工作表；
- 结果可追溯到原始文件、链接或页码；
- 多库隔离和 strict 模式不被破坏。

## 5. 内容治理

### 必须遵守

- 对话附件默认不入库；
- 外部资料默认先结构化，不原样成为正式知识；
- Agent 只能提议保存，不能静默写入；
- 正式知识必须有来源；
- 用户确认知识优先于 Agent 未确认内容；
- 原文只作为来源和回退材料。

### 后续能力

- `kb_propose_update`：差异预览后更新已有知识；
- 重新解析和版本比较；
- 用户整理和 Agent 整理的来源标记；
- 向量召回与混合检索。

## 6. 云文档与 Office 的位置

云文档浏览器、导出下载和 Office 解析是来源接入能力，不是知识库核心。

开发顺序应为：

1. 先保证本地附件可整理；
2. 再保证 DOCX/PDF/XLSX 可提取；
3. 再补 WPS、飞书、Google 等网页来源；
4. 最后评估批量同步和平台 API。

WPS 导出失败不能阻塞知识库主线，也不应继续投入高保真页面还原。

## 7. 暂停或降级的方向

- WPS/Office 高保真预览；
- 原始云文档实时代理；
- 原样文档作为知识库主内容；
- 复杂的来源目录和项目绑定；
- 向量库（片段索引未稳定前）；
- 无人值守自动写入。

## 8. 当前开发闸门

在以下条件满足前，不继续扩展平台适配：

- ✅ 聊天附件可被 Agent 读取（`kb_read_attachment` 已完成）；
- ✅ Agent 可通过 `kb_read_attachment` + `kb_propose_save` 生成并提交结构化草稿，待真实附件场景验收；
- 用户确认后可保存（`kb_propose_save` 已具备，待与草稿串通）；
- ✅ 知识可按片段检索（当前为进程内关键词检索，SQLite FTS 待后续）；
- 结果能显示来源位置。

## 9. 给开发者的一句话

> 先把资料变成 Agent 能快速检索的知识，再考虑如何更好地展示原始文档。
