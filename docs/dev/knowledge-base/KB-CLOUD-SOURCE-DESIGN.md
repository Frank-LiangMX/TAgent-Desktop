# 云文档来源设计

首次定稿：2026-08-25
最后更新：2026-08-26
状态：P0 浏览器快照导入和直链文件导入已落地；P1 页面结构化提取与重新抓取待推进；平台 API 不作为主流程

## 产品定义

“云文档导入”接收 WPS、飞书、Google Docs 等云文档的分享页面地址，不要求用户寻找直接下载地址，也不要求为每个平台申请 App ID/Secret。

例如：

- WPS：https://365.kdocs.cn/l/...
- 飞书：https://xxx.feishu.cn/docx/...
- Google Docs：https://docs.google.com/document/d/.../edit

## 统一导入流程

粘贴分享链接 -> 在 TAgent 内置浏览器打开 -> 用户在该浏览器内登录或扫码 -> 用户进入文档正文 -> TAgent 读取当前页面可见内容 -> 保存为知识库文档快照，同时保存原始链接和抓取时间。

登录发生在内置浏览器的持久化会话中。TAgent 不读取外部浏览器的 Cookie，也不把账号密码或平台令牌写入知识库。

## 当前实现边界

当前有两条导入路径：

1. 直链文件导入：当地址直接返回 DOC、DOCX、PDF、Markdown 或 TXT 文件时，主进程下载文件并使用本地解析流程。
2. 分享页面导入：当地址需要登录或返回网页编辑器时，在独立内置浏览器窗口中完成登录，用户点击“读取当前网页”后保存浏览器快照。

分享页面导入采用浏览器渲染后的 DOM 内容提取，不是屏幕截图、OCR，也不是对页面源码做 grep。当前提取器会过滤常见页面控件，并对标题、列表、表格、链接、强调文本和代码块做 Markdown 化；但平台页面的编辑器、虚拟列表和复杂布局仍可能产生顺序错乱、控件噪声或内容不完整。

如果页面仍停留在登录页、正文太短或平台使用 Canvas 绘制正文，系统应提示用户先进入真实文档正文；后续通过平台级正文选择器和滚动加载策略解决。

## 数据模型

知识库文档除了快照正文，还保存：

- sourceUrl：实际读取页面的原始地址
- sourceProvider：目前保留平台识别字段；浏览器导入无法稳定识别时使用 unknown
- sourceAccessMode：public / oauth / browser；浏览器快照使用 browser，直链文件使用 public
- sourceSyncedAt：快照抓取时间

知识库保存的是快照，不是实时代理。后续可以提供手动重新打开来源并重新抓取，而不是每次 Agent 回答都请求外部平台。

## 交互要求

1. 用户只需要粘贴分享链接，可以附带标题。
2. 点击“在内置浏览器打开”后，用户在 TAgent 内完成登录或扫码。
3. 用户进入文档正文后点击“读取当前网页”，明确确认后才写入知识库。
4. 成功导入后显示原始链接、访问方式和快照时间。
5. 读取失败要区分链接格式错误、仍在登录页、正文太短和平台页面无法提取。
6. 外部浏览器可以继续使用，但它的登录状态不会自动提供给 TAgent；需要在 TAgent 内置浏览器里完成一次登录。

## 开发顺序

### P0：统一浏览器入口（已完成）

- 使用现有内置浏览器的持久化会话打开任意云文档 URL。
- 增加当前页面正文提取 IPC。
- 从知识库页面执行“读取当前网页”并保存快照及来源元数据。
- 继续支持本地 DOC、DOCX、PDF、Markdown、TXT 导入。
- 独立浏览器窗口使用 TAgent logo，标题带“内置浏览器”标识。

### P1：页面兼容性增强（下一步）

- 对 WPS、飞书、Google 等常见页面增加正文区域选择器和滚动加载策略。
- 过滤编辑器工具栏、目录、评论、协作者、表情等页面噪声，避免把页面参数写入正式文档。
- 保留标题、层级、列表、表格、代码块和链接的结构化 Markdown。
- 对 PDF 页面增加浏览器内 PDF 文本提取或明确提示用户上传本地 PDF。
- 增加重新抓取、版本比较和失败时保留旧快照。

### P2：可选的平台 API 适配

只有在确实需要批量同步、后台同步或页面无法渲染提取时，才单独评估平台官方 API。API 适配应作为可选能力，不得成为普通云文档导入的前置条件。

## 设计结论

“网页登录 + TAgent 内置浏览器读取正文”是默认路径；平台 OAuth 不是默认路径。这样用户面对的是一个统一入口，而不是 WPS、飞书、Google 各自一套配置页面。
