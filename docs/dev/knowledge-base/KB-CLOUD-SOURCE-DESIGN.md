# 外部文档来源与解析设计

首次定稿：2026-08-25
重构日期：2026-08-28
状态：来源获取是辅助能力，不是知识库主流程

## 1. 设计结论

WPS、飞书、Google Docs 等云文档链接的职责只有一个：提供 Agent 可读取的外部资料。

系统不再把云文档页面做成 Office/WPS 阅读器，也不以还原原始页面排版为目标。云文档最终要进入“读取 → 结构化 → 用户确认”的知识处理链路。

## 2. 统一入口

用户可以：

- 在聊天中粘贴云文档分享链接；
- 在聊天中上传从云端导出的本地文件；
- 在知识库页面使用来源导入作为辅助入口。

优先路径是聊天。知识库页面的导入入口只作为批量导入和异常兜底，不应要求用户先进入知识库。

## 3. 获取与解析边界

### 获取层

- 识别分享链接中的 HTTP(S) 地址；
- 使用 TAgent 内置浏览器打开需要登录的页面；
- 用户在内置浏览器中登录、扫码并进入正文；
- 读取页面正文，或捕获用户明确触发的本地导出文件；
- 记录来源链接、访问方式和抓取时间。

### 解析层

- 将 DOCX、PDF、XLSX、网页正文转换为统一中间格式；
- 保留标题层级、段落、表格、代码、列表、工作表和来源位置；
- 不追求像素级还原；
- 解析不确定时生成待审核状态，不伪造内容。

### 知识层

- Agent 根据资料生成结构化知识草稿；
- 用户确认后才进入正式知识；
- 结构化知识切分后参与检索；
- 原始文件或页面不作为正式知识主内容。

## 4. 来源记录

正式知识至少记录：

- `sourceName`：文件名或页面标题；
- `sourceUrl`：原始链接（如有）；
- `sourceProvider`：wps / feishu / google-drive / unknown；
- `sourceAccessMode`：public / browser / local；
- `sourceLocation`：页码、工作表、章节或段落；
- `sourceSyncedAt`：读取时间；
- `parseStatus`：parsed / needs-review / failed。

来源记录服务于引用、追溯和重新处理，不代表系统要持续代理云文档。

## 5. WPS 与 Office 的处理原则

- WPS 网页登录只用于取得用户有权访问的内容。
- 不要求申请平台 App ID/Secret 作为普通导入前置条件。
- “导出为 DOCX/XLSX”只是获取源材料的方式，不是知识库最终格式。
- WPS 页面中的工具栏、评论、协作者、目录和页面参数不得进入正式知识。
- XLSX 多工作表应拆成可分别处理的结构化输入。
- DOCX/PDF 的原始版式不作为解析成功标准。

## 6. 失败策略

失败应明确区分：

- 链接中没有有效 HTTP(S) 地址；
- 仍停留在登录页；
- 页面没有可读正文；
- 导出文件未生成或格式无法识别；
- 结构化解析存在不确定内容；
- 用户没有访问权限。

失败时保留错误信息和来源，不生成看似完整但实际错误的知识。

## 7. 当前状态

已具备：

- 内置浏览器登录和网页正文读取基础能力；
- 本地 DOC、DOCX、PDF、Markdown、TXT 导入基础能力；
- XLSX 多工作表拆分基础能力；
- 云文档来源元数据；
- 原始下载捕获的实验能力。

未完成：

- 聊天附件到结构化知识草稿的主链路；
- 通用 DOCX/PDF/XLSX 中间格式；
- 片段级索引；
- 失败后的可视化审核和重新处理；
- WPS 特定导出行为的稳定兼容。

## 8. 开发优先级

1. 先打通本地附件和 Agent 整理，不阻塞于 WPS。
2. 建立统一解析中间格式和来源位置。
3. 为长文、表格和多工作表建立知识片段。
4. 再补云文档网页读取和导出兼容。
5. 最后评估平台 API、批量同步和高级格式恢复。

## 9. 明确不做

- 不做 WPS/Office 的完整替代品；
- 不以屏幕截图或 OCR 作为默认解析方式；
- 不把云文档实时代理到每次 Agent 回答；
- 不把高保真排版作为知识入库前提；
- 不因某个平台的导出问题阻塞知识库核心流程。
