# 知识库产品规范（重构版）

首次定稿：2026-08-25
重构日期：2026-08-28
状态：当前生效

> 当前最高优先级决策见 [KB-DESIGN-DECISION.md](./KB-DESIGN-DECISION.md)。本文替代旧版关于原样文档和云文档快照作为主内容的描述。

## 1. 一句话定位

知识库是一层经过用户确认的结构化知识，供 Agent 快速检索、引用和复用。

它不是 Office/WPS 阅读器，不是原始文件网盘，也不是把外部文档原样搬进应用。

## 2. 核心工作流

```text
聊天附件 / 本地文件 / 云文档链接 / 粘贴文本
                    ↓
              Agent 读取与解析
                    ↓
        提取事实、规则、步骤、表格、代码和例外
                    ↓
        生成符合知识类型规范的结构化草稿
                    ↓
              用户预览并确认
                    ↓
          写入知识库，切分并建立检索索引
```

外部资料是输入，结构化知识才是正式内容。

## 3. 核心对象

- **KnowledgeBase**：应用级知识集合，不要求绑定项目路径、工作区或具体目录。
- **SourceMaterial**：外部来源材料，包括聊天附件、本地文档、云文档链接、网页内容和粘贴文本。用于追溯和重新处理，不是 Agent 的主要检索对象。
- **KnowledgeDocument**：经过 Agent 或用户整理、并经用户确认的正式知识文档。
- **KnowledgeChunk**：从正式知识文档切分出的检索单元，每个片段尽量表达一个完整事实、规则、步骤或结论。
- **SessionBinding**：会话选择使用哪些知识库，以及使用模式：不使用、优先使用、仅使用。

## 4. 内容生命周期

1. **对话材料**：聊天附件默认只用于当前任务，不自动入库。
2. **结构化草稿**：Agent 读取资料后生成，可预览和修改，但不能作为正式知识检索。
3. **正式知识**：用户确认后写入，可被 Agent 检索和引用。
4. **来源记录**：保存文件名、链接、页码、工作表、章节或其他位置标记。

原始文件只作为来源缓存、追溯依据和解析失败时的回退，不要求高保真还原，也不作为知识库主 UI 内容。

## 5. 外部资料导入规则

外部文档进入知识库时，默认经过 Agent 整理，不原样创建为正式知识文档。

- DOCX、PDF、XLSX：提取正文、标题、表格、代码和工作表信息。
- 表格：整理为字段、规则、枚举、记录和示例，避免只生成平铺 Markdown。
- 长文：切分为多个有标题和来源位置的知识单元。
- 版式复杂或解析不确定：标记待审核，不伪造内容。
- 云文档浏览器和平台下载只负责获取资料，不决定知识库的内容形态。

## 6. 结构化知识规范

统一元数据：

```text
title       标题
kind        note / norm / contract / guide / reference / snapshot
summary     一句话摘要
content     结构化正文
source      来源和位置
author      user / agent
status      draft / confirmed / archived
updatedAt   更新时间
```

正文按类型使用模板：

- `contract`：入口、参数、返回、前置条件、禁忌、示例
- `norm`：适用范围、必须、禁止、例外、正反例
- `guide`：目标、前置条件、步骤、验证、故障处理
- `reference`：概念、字段、关系、枚举、来源
- `snapshot`：探查时间、范围、数据、结论、更新方式
- `note`：普通结构化笔记

不是所有文档使用同一套正文模板，但正式知识必须可定位、可引用、可追溯。

## 7. Agent 契约

- 收到外部资料后先读取和整理，不自动保存。
- 用户要求整理时生成结构化草稿，并展示来源和不确定内容。
- 用户确认后调用 `kb_propose_save` 写入正式知识。
- 用户拒绝或会话中止时，不产生正式知识。
- 只有工具返回 `ok:true` 才能声称保存成功。
- 检索时先用 `kb_search` 定位片段，必要时再用 `kb_get` 读取全文。
- 资料冲突时展示来源并提示用户确认，不自行覆盖正式知识。

## 8. 检索契约

`kb_search` 的主要返回单位是知识片段，而不是整篇文档：

```text
knowledgeBaseId
documentId
title
kind
section
excerpt
sourceLocation
score
```

优先级建议为：用户确认知识 > 用户整理内容 > Agent 整理内容 > 未确认草稿。未确认草稿不得作为正式答案依据。

## 9. UI 边界

聊天负责资料提交、Agent 整理、草稿预览和确认保存。

知识库页面负责搜索、浏览、查看来源、编辑、归档和删除正式知识。

云文档浏览器、原始文件下载和 Office 高保真预览属于辅助能力，不应占据知识库主流程。

## 10. 会话模式

| 模式 | 行为 |
| --- | --- |
| 不使用 | Agent 不使用知识库 |
| 优先使用 | 回答前先检索；知识库不足时可使用通用能力并区分来源 |
| 仅使用 | 只能依据知识库；没有依据时明确说明未找到 |

## 11. 开发范围

### 已完成基础

- 应用级知识库和会话绑定；
- 正式知识文档 CRUD；
- `kb_search`、`kb_get`、来源引用和受控写入；
- 本地文档、云文档和聊天附件的基础入口；
- 聊天附件 Agent 读取与解析（`kb_read_attachment`：DOCX/PDF/XLSX/MD/TXT/CSV 统一中间格式，会话隔离、零写入、不自动保存）。

### 下一阶段：结构化 ingest 与检索 MVP

- ✅ 聊天附件进入 Agent 解析链路（`kb_read_attachment`）；
- ✅ DOCX/PDF/XLSX/MD/TXT/CSV 统一转为结构化中间格式（文本 / 各工作表）；
- 👉 **下一步：Agent 基于解析结果生成结构化草稿，展示来源与不确定内容，用户确认后经 `kb_propose_save` 写入正式知识。**
- 文档切片、关键词/全文索引；
- 搜索返回片段、章节和来源位置；
- 网页正文与云文档链接的统一解析（后续辅助能力）。

### 后续按需

- 向量召回和混合检索；
- 重新处理、版本比较和差异确认；
- 更强的表格、图片和复杂 PDF 解析；
- 云平台批量同步。

## 12. 明确不做

- 不把知识库做成 WPS/Office 替代品；
- 不强求原始排版高保真还原；
- 不把每个外部文件原样作为正式知识；
- 不让 Agent 静默写入正式知识；
- 不要求 Agent 逐篇翻阅完整文档；
- 不以项目路径作为知识库前提；
- 不把平台 OAuth 或 App ID/Secret 作为普通导入前置条件。

## 13. 验收标准

1. 用户可以在聊天中直接提交文档，不必先进入知识库页面。
2. Agent 能生成带标题、类型、来源和结构的草稿。
3. 未确认草稿不会被正式检索。
4. 确认后的知识可以按片段快速命中，并展示来源位置。
5. 原始文件不需要完整还原，也不会阻塞结构化知识入库。
6. 知识库页面不承担 Office/WPS 阅读器职责。
