# 知识库 v2 产品模型

首次定稿：2026-08-25
最后更新：2026-08-26

## 一句话定位

知识库是一组可持续积累、可编辑、可检索、可跨项目复用的确认过的知识文档。

## 核心对象

- KnowledgeBase：知识库本身，只描述用途和边界。
- KnowledgeBaseDocument：知识库中的正式文档，当前以 Markdown 正文保存。
- KnowledgeBaseSource：可选的外部目录来源，用于导入/检索，不是知识库本身。
- SessionBinding：会话选择知识库 ID，只影响当前 Agent 可检索范围。

## 触发原则

- 阅读资料：临时使用，不入库。
- 整理资料：先生成草稿，不自动保存。
- 明确保存：用户确认后写入指定知识库。
- Agent 建议：只能提示“是否保存”，不能自动创建或写入。
- 上传/导入：用户明确选择目标知识库后才能入库。

## 第一阶段范围

- 全局知识库列表和详情页。
- 直接新建、编辑、保存 Markdown 文档。
- 文档列表、标题/正文搜索、预览。
- 保留现有来源目录管理和会话选择。
- 文档删除需要明确确认。

## 暂不做

- Agent 未确认自动写入。
- 向量数据库和自动知识抽取。
- 复杂权限、版本分支和外部服务同步。
- Office/PDF/OCR 的高保真结构化解析。

## 验收标准

- 用户无需先选择项目或目录即可创建知识库。
- 用户可以在知识库内直接创建一篇文档并再次打开编辑。
- 会话选择知识库后，Agent 仍可使用已有检索能力。
- 阅读资料不会改变知识库；只有明确保存才会新增文档。

## 2026-08-26 实施进度

### 已完成

- 知识库作为应用级资源落地，不再要求绑定项目路径或工作区目录。
- 知识库管理页、知识库概览页、文档阅读和编辑页已可使用。
- 页面状态已收口为知识库总览、知识库概览、文档阅读三种状态，不自动选中第一篇文档。
- 知识库侧边栏负责导航，统计信息只在主区展示，新建知识库入口收口到侧边栏。
- 本地 Markdown、TXT、DOC、DOCX、PDF 导入和云文档浏览器快照导入已接入。
- 会话级知识库选择和“不使用 / 优先使用 / 仅使用”模式已接入 Pi 与 kscc 的运行配置。

### 尚未完成

- 界面保存的正式文档尚未纳入 Agent 的统一检索索引，当前 Agent 检索闭环仍以绑定本地目录为主。
- 检索结果的来源引用展示、文档级全文读取和中文检索质量仍需补齐。
- DOC、DOCX、PDF 与云文档的结构化解析仍属于 best-effort，尚未达到高保真。
- “保存为知识文档”“整理后更新”以及 candidate -> confirm -> active 写入门控尚未实现。
- 版本、重新抓取、差异比较和失败回滚尚未实现。

## 开发闸门

下一阶段先完成“正式文档接入检索、会话隔离、来源标注”的最小闭环，再评估 Agent 整理和成稿能力。未完成检索闭环前，不扩大到向量库、自动抽取或无人值守写入。
