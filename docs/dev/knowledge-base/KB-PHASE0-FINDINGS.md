# 知识库实现记录

日期：2026-08-28
重构记录：2026-08-28
状态：基础底座完成；结构化 ingest 和片段检索尚未完成

## 1. 当前产品判断

前期实现验证了知识库的基本底座，但也暴露出方向偏移：

- 已经做出知识库页面、文档 CRUD、来源导入和云文档浏览器；
- Agent 可以检索正式文档并通过确认横幅提议保存；
- 但外部文档仍主要被当作“要保存和展示的文档”；
- 检索仍以整篇文档和关键词为主；
- 这更接近文档管理器，而不是 Agent 知识库。

新的主线是：外部资料进入 Agent 解析链路，转化为结构化知识和可检索片段。

## 2. 已完成的底座能力

- 应用级知识库，不要求绑定项目路径；
- 会话级知识库选择和不使用 / 优先使用 / 仅使用模式；
- 正式知识文档创建、编辑、删除；
- `kb_search`、`kb_get` 和来源引用；
- `kb_propose_save` 受控写入；
- 本地 Markdown、TXT、DOC、DOCX、PDF 的基础导入；
- XLSX 多工作表的基础拆分；
- 云文档链接和内置浏览器基础入口；
- Pi 与 kscc 双 Agent 工具挂载；
- 知识库与记忆系统隔离。

## 3. 当前不应继续扩大的能力

以下能力保留为辅助或实验能力，不再作为知识库主线：

- WPS/Office 原始排版还原；
- 云文档页面高保真复制；
- 原始文档作为正式知识主内容；
- 导入页面中的复杂编辑和预览；
- 平台 OAuth、App ID/Secret 和实时同步；
- 为每个平台建立一套独立导入交互。

## 4. 下一阶段必须完成

### A. 聊天资料入口

用户可以在聊天中上传 DOCX、PDF、XLSX 或粘贴链接，Agent 直接读取资料并整理，不要求用户先进入知识库页面。

### B. 统一解析中间格式

至少表达：

- 标题层级；
- 段落；
- 列表；
- 表格；
- 代码；
- 工作表；
- 来源位置；
- 解析警告。

### C. 结构化草稿

Agent 需要根据资料类型生成：

- 规范；
- 接口约定；
- 操作指南；
- 参考资料；
- 统计快照；
- 普通笔记。

草稿必须包含来源和不确定内容，且不能直接参与正式检索。

### D. 片段级检索

正式知识保存后：

- 按标题和语义边界切分；
- 片段带文档、章节和来源位置；
- `kb_search` 返回少量相关片段；
- `kb_get` 仅用于按需读取全文。

## 5. 现有数据模型调整方向

现有 `KnowledgeBaseDocument` 可以继续作为正式知识的兼容载体，但需要逐步增加：

- `kind`：知识类型；
- `summary`：摘要；
- `source`：来源记录；
- `author`：user / agent；
- `status`：draft / confirmed / archived；
- `chunks` 或独立片段索引；
- `parseWarnings`：解析警告。

原始文件不必塞进正式文档正文，可以作为来源附件或临时缓存。

## 6. 验收清单

### 资料整理

- [ ] 聊天附件可被 Agent 读取；
- [ ] Agent 能区分普通总结和整理入库；
- [ ] 结构化草稿可预览；
- [ ] 用户确认前不写入正式知识；
- [ ] 拒绝或取消后不产生正式知识。

### 解析质量

- [ ] 标题层级不被压平；
- [ ] 表格可表达字段和记录；
- [ ] 多工作表可以分别定位；
- [ ] 代码块保持代码语义；
- [ ] 解析异常可见。

### 检索质量

- [ ] 大文档不需要逐篇翻阅；
- [ ] `kb_search` 返回片段而非只有整篇文档；
- [ ] 命中结果包含来源位置；
- [ ] 多库隔离有效；
- [ ] strict 模式无依据时不编造。

## 7. 当前开发顺序

1. 聊天附件 → Agent 读取；
2. 统一解析中间格式；
3. Agent 结构化草稿；
4. 用户确认保存；
5. 知识片段切分和索引；
6. 来源引用和检索验收；
7. 最后再补云文档兼容。
