# 知识库实现记录

日期：2026-08-26
状态：Phase 0 已完成；Phase 1 的存储、管理界面和导入能力已落地，Agent 检索正式文档的闭环待推进

## 当前已落地

知识库已经是应用级资源，与项目、工作区和会话解耦：

- 在左侧 Rail 打开知识库管理页。
- 知识库列表页只展示全局统计；新建入口位于知识库侧边栏。
- 进入知识库后，主区默认展示该库统计，不自动打开第一篇文档。
- 选择文档后进入阅读/编辑页；文档列表整行可点击。
- 知识库内可以直接新建、编辑、保存和删除 Markdown 文档。
- 支持导入本地 Markdown、TXT、DOC、DOCX、PDF；DOCX/PDF 有 OfficeCLI 优先和内置兜底解析，旧版 DOC 仍依赖 OfficeCLI 或转换为 DOCX。
- 支持粘贴云文档分享地址，在 TAgent 独立的内置浏览器中登录、打开正文并读取当前页面，保存为带来源信息的快照。
- 会话可以选择多个知识库，并设置“不使用 / 优先使用 / 仅使用”三种知识范围模式。
- 知识库工具已同时挂载到 Pi 和 kscc：kb_list_roots、kb_search、kb_get。
- 知识库与 L0-L5 Frozen memory、BotMemory 保持隔离；读取和检索不会自动写入任何记忆。

## 当前实现边界

### 已经可以使用的链路

1. 用户创建知识库。
2. 用户在库内创建或导入正式文档。
3. 用户在界面中阅读、预览、编辑和保存文档。
4. 会话选择知识库后，Agent 可以按当前模式检索已绑定的本地来源目录。

### 尚未闭环的链路

- 当前 Agent 工具的检索实现仍主要面向知识库绑定的本地目录，只检索 .md、.markdown、.txt 文件。
- 界面中保存的正式文档位于应用配置目录的 JSON 存储中，目前还没有接入同一套 Agent 检索索引。因此，“界面里能看到的文档”与“Agent 能搜到的文档”仍可能不一致。
- 当前还没有 FTS5/SQLite 索引、文档切片、引用卡片、检索排序和中文召回优化。
- Agent 仍然是只读工具，没有“保存为知识文档”“整理后更新”的 candidate -> confirm -> active 写入链路。
- 云文档读取使用通用 DOM 可见内容提取，标题、代码块、表格和页面噪声仍需要按平台继续提高稳定性。
- 当前没有版本链、重新抓取后的差异比较和旧快照保留策略。

## 存储

- 知识库配置：应用配置目录的 knowledge-bases.json。
- 正式文档：应用配置目录的 knowledge-base-documents.json。
- 会话元数据：保存 knowledgeBaseIds、knowledgeBaseMode；旧会话的 kbRoots 仍兼容。
- 本地来源目录仍由独立文件索引处理，不复制或修改用户原文件。
- 删除知识库只删除应用内配置和正式文档，不删除来源目录。

## 当前验证

已完成：

- 知识库相关单测：bun test apps/electron/src/main/lib/kb
- Electron renderer 构建：bun run --cwd apps/electron build:renderer
- Electron 类型检查：bun run --cwd apps/electron typecheck
- 文档和代码变更执行 git diff --check

仍需补充的验收：

- 同一篇正式文档在知识库界面、Pi 和 kscc 中均可检索。
- 多库绑定时只能命中当前会话授权的库。
- “优先使用 / 仅使用”模式在真实 Agent 回答中满足各自约束。
- DOC/DOCX/PDF、云文档分享页的结构化内容在导入后保持可读。
- 删除、更新和重新导入不会留下错误索引或旧内容。

## 下一步开发顺序

### P1-1：正式文档接入 Agent 检索

把 knowledge-base-documents.json 纳入知识库检索服务，统一界面文档与 Agent 工具的数据源。第一版先做标题、正文关键词检索和全文读取，不引入向量库；结果返回文档 ID、标题、摘要和来源元数据。

### P1-2：会话检索闭环

补齐多库隔离、检索结果来源标注和真实 Pi/kscc 端到端测试，确保三种知识范围模式不是只停留在系统提示词层面。

### P1-3：导入质量

继续增强 DOC/DOCX/PDF 的标题、段落、列表、表格和代码块转换；导入失败时明确区分无文本、扫描件、解析失败和格式不支持。

### P1-4：云文档快照质量

针对 WPS、飞书、Google Docs 等页面增加正文区域识别、滚动加载和页面控件过滤；保留原始快照，后续再做重新抓取和版本比较。

### P1-5：明确写入动作

在 Agent 对话中增加“保存为知识文档”和“整理后更新”，但必须经过用户确认和差异预览，不能开放静默写入。

## 明确暂不做

- 向量数据库、OCR 和 PixelRAG。
- Agent 无人值守修改正式知识。
- BotMemory 与知识库合并。
- 复杂权限、版本分支和平台专属 API 作为普通导入前置条件。
- 多视图导出和重型 Office 高保真排版。
