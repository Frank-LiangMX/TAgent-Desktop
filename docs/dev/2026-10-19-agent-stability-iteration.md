# TAgent 稳定性开发与验证记录

日期：2026-10-19。此轮承接 [故障调查与前序修改](./2026-10-19-stream-stability-review.md)。代码已修改并完成本地自动验证，未提交 Git commit，未重启用户应用。

## 本轮结果

### 子代理在预算内收尾

原先固定 20 次工具调用、120 秒，并在第 21 次调用直接 abort。现在创建子代理时告知预算，达到工具预算或进入时间收尾窗口后，在下一次模型请求中移除工具并要求生成阶段报告。

| 任务复杂度 | 工具调用预算 | 总时限 |
| --- | ---: | ---: |
| simple | 20 | 120 秒 |
| standard（默认） | 40 | 300 秒 |
| complex | 80 | 600 秒 |

收尾最多 30 秒，包含在总时限内。工具调用按尝试次数计数，批量调用逐项计数；超过预算的工具不执行。模型拒绝收尾、请求卡住或工具卡住仍可能失败，不承诺所有任务一定产生报告。

有效阶段报告标记为 `partial`，明确尚未全部完成；真正完成、失败、用户停止分别使用 `completed`、`failed`、`stopped`。失败保留首个原因和最后非空文字，避免后续 aborted 或空消息覆盖证据。结构化结果保留 outcome、budgetReason、failureReason、stopReason、调用次数和耗时。

后台回投、主代理工具错误标记、任务卡片和历史恢复同步处理这些状态。历史只解析工具结果开头的固定状态标记；旧数据仍兼容 isError。已结束任务不会因迟到的 started/progress 重新变成运行中。

这一策略替代前序调查记录末尾“本次未提高限制”的旧实现。默认任务预算增加，也意味着复杂任务可能使用更多时间和模型额度。

### 明确消息快照的含义

Pi 适配器发出的 assistant 内容标记 `_contentSnapshot: true`，表示该消息完整、有序的内容快照。前端按 UUID 更新，跳过旧的“补到最后一条消息”“保留更长文本”等猜测性合并。

因此不同 UUID 不会互相覆盖；同一消息的最终快照可以合法缩短或删除草稿块；终态不会被迟到的 partial 覆盖。正文和思考保持原始块顺序。未标记的旧消息仍走兼容路径。

前序修改也纳入本次回归：同步接收流式增量、显示层按时间推进文字、保留布局切换前缀、移除标点改写、简化生成文风、移除输入框上方终端悬浮入口，以及阻止 SDK 将不适合回传的历史 thinking 转成正文。

## 验证证据

最终执行 `bun run test:agent-stability`：**25 个文件、308 项测试通过**，退出码 0。该命令已加入根 package.json，便于后续修改重复验证。

覆盖的关键场景：

- 三个真实 Pi 子代理并行运行，经本地 HTTP 返回批量工具调用；各执行 20 次后成功收尾为阶段结果。
- 模型无视收尾指令、时间预算进入收尾窗口、用户停止、HTTP 错误、空最终回复及容量释放。
- 本地 Anthropic SSE → 真实 Pi → 生产 IR 转换 → 生产消息 reducer → JSONL 序列化/历史加载 → 展示模型的一致性；正常结束与中途 HTTP 错误均覆盖。
- 重复终态、迟到 partial、稳定消息身份、正文/思考类型保持、实时与历史任务状态一致。
- 分批文字的显示节奏、Unicode 字素、减少动态效果、最终尾文排空、路径/引号等标点保真。

Electron、shared、pi-core、UI 的类型检查通过。Pi-core、Electron 主进程和 renderer 构建通过。Renderer 仍报告大 chunk 及静态/动态混合导入警告，构建未失败。`git diff --check` 通过。

## 验证边界与使用方式

HTTP 测试使用本地受控响应和真实 SDK，不调用用户真实模型渠道。回放案例依据故障形态构造并脱敏，不是原始事故 SSE；原始事故没有完整线级响应，因此三个历史任务的预算触发原因仍是高置信推断。

尚未完成实际 Electron 中的主观流畅度验收，也未验证真实网关对 DeepSeek 空签名 thinking 回传的兼容性。显示缓冲只能平滑已经收到的文字，无法消除上游长时间停发。已被写成普通 text 的旧思考内容不会自动清洗。

使用新代码需要重新加载包含本轮构建的主进程；文风与历史思考回传适合用新会话验证。当前结论是多处已复现的状态处理、预算收尾和 SDK 适配缺陷得到修复，不能据此声称所有渠道均已稳定，也不足以断言必须更换整个 Pi 框架。
