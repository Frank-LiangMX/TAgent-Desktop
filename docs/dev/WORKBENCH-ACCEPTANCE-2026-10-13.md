# 工作台自动验收 · 2026-10-13

本轮覆盖日常工作台操作、数据持久化、完整应用启动，以及 Pi / Codex / Claude 三种运行时的真实模型调用。所有写入均使用隔离配置目录与合成内容，没有向用户的正式工作台、知识库或会话写入验收数据。

## 结论与发现

- 最终 40 个测试文件、379 项回归测试全部通过；全仓类型检查、renderer / main / preload 构建和默认构建产物检查通过。
- 三种运行时均实际调用工作台工具，读取当天待办和日程，再通过第二轮对话保存带标签的随笔。模型使用现有 HTTP 渠道的 `gpt-5.6-luna`；不是模拟模型输出，也不是仅检查工具名称。
- 发现 Codex 当前版本通过 freeform JavaScript `exec` 入口暴露动态工具。HTTP 协议转换原先忽略 `custom` 工具，导致工作台工具虽然注册成功，模型仍无法调用。现已补齐请求包装、返回转换、工具命名空间与后续轮次的调用历史。
- 发现 HTTP 200 的 SSE 流可能包含上游错误，例如服务器繁忙。原转换器忽略该错误并生成“成功完成”，导致空回复。现已向 Codex / Claude 正确传递失败，覆盖末帧没有分隔符的情况。
- Claude MCP 复用工作台工具的实际 JSON Schema、取消信号及请求标识；会话装配失败会显式报错，避免静默缺少工具。
- 修复日期相关测试中的固定日期依赖与不支持的查询参数；更新仍断言“只能使用 Pi”的旧验收约束。普通构建允许三运行时，对外构建继续检查 Claude SDK 排除边界。

## 验证边界

- 文件选择对话框自动指定隔离路径；验证了真实 IPC 与文件内容，没有操作 Windows 文件选择器本身。
- 链接抓取使用本地合成网页，流程中的示例整理稿明确标为模拟；另有三运行时的真实模型工作台读写验收。没有宣称抖音、小红书的登录限制、视频转写或任意站点抓取已通过。
- WPS 登录、权限、采集、日报与自动化有回归测试；本轮未重新扫码或实际抓取用户 WPS 云端聊天/文档，不能据此断言开放平台权限已齐全。
- 真实模型测试使用一个已配置的 HTTP Chat 渠道。其他协议转换有回归覆盖，但没有逐一实测所有渠道/模型。上游繁忙和网络耗时仍由服务端决定。
- 验证的是本地默认构建，没有生成、安装或验收新的安装包，也没有运行对外裁剪构建。
