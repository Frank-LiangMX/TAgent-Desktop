## 3. 关键边界（给实现 agent 的硬约束）

1. **外部渠道受限**：A2A 工具桥只对 **kscc-internal** 与 **Anthropic 协议（`isAgentCompatibleProvider`，如 anthropic）外部渠道** 开放；OpenAI-completions / google / zhipu / doubao / qwen 等走纯文本 runner（fail-closed，`channelSupportsRoomToolBridge()===false`），**绝不通过 prompt 文本伪造工具**。
2. **协作室成员不能直接调用系统子代理**：工具白名单只有 `room_send / room_ask / room_reply / room_task_update` 四把 TypeBox 受限工具，`additionalProperties:false` 锁死；**不复用** Pi 会话的 Read/Bash/Edit/Write/Task 等。
3. **协作室成员不能直接读写看板真值**：看板真值仍归 kanban（ADR-0007 不变量 §15.7）；room 只在未挂板时维护轻量 room task，挂板后 `create/update` fail-closed。`room_task_update` 只能改**自己名下**的房间任务，且只能改状态 + 记 summary 事件。
4. **A2A 安全字段宿主补齐**：`roomId/memberId/depth/rootMessageId/causationId` 不接受模型传入；`fromMemberId` 恒取 run 的 memberId。
5. **成员正文 `@` 永不投递**：`resolveCollaborationMentions` 的发送者闸保证。
6. **不要**另起一套与 mailbox 平行的 Hermes handoff 表；深度保持房间 `maxA2ADepth`（默认 4，硬上限 10），`continueDepthStop` 一次仅 +1 且仍受硬上限。

## 7. 推荐下一步开发顺序

> 与旧的「先 S3.5 再 S4」不同，S3.5/S4 主体已通。现在建议按影响面与风险排：

1. **（可选先做）看板桥（S5 收尾）** —— 让 `attachedBoardId` 变成真实投影：看板 task 状态 → 房间事件，房间不反向覆盖。触及「看板真值」共享依赖，需与 kanban 侧协调。
2. **体验/生产化收尾（S5 面板 + S6 轻量子集）**：右侧任务/产物面板（从消息定位 task/run）→ 权限档位 `permissionProfile` 强制 → 预算字段在 run 侧 fail-closed 判 80% 警告/硬截止。
3. **产物发布 `room_publish_artifact` + 文件校验**（相对路径/hash/权限）。
4. **CLI worker 成员后端 adapter**（`backend==='cli'`）。
5. **S6 并发写入与生产化**（worktree/租约、injection 隔离、时间线虚拟化、导出审计）。
6. **合 main 门槛**：全量 vitest + electron typecheck + 手测 Rail 不破坏 Chat / kscc 默认可聊 / `@` 并行 / 取消 / 重启无假 running / A2A ask-reply 闭环 / 深度停止卡。

> 每切片仍按「纵向可测试闭环」提交；**不要**按「先把所有 UI / 再把所有 backend」横切。合 main 前不得把未完成 A2A/产物/看板宣传成「完整数字员工」。

## 9. 红线（给 agent 的硬约束）

1. 禁止把 room 消息写入普通 session JSONL 当「同一会话」。
2. 禁止一个模型上下文扮演多个成员却标成多 Agent。
3. 禁止未确认副作用时自动重放 interrupted run / 已 dispatch 的 A2A 信封（只可安全重投 `outbox` 且未关联 target run 的窗口）。
4. 禁止 Agent 自行改成员权限/预算/无限拉人；`room_task_update` 只能改自己名下任务状态。
5. 禁止用 prompt 文本伪造 A2A 工具；外部非 Anthropic 协议渠道一律 fail-closed 纯文本。
6. 功能开发在 **`feature/collab-room`**；合 main 走 PR。
