## 2. 产品定稿（实现时不可违背）

详见 ADR-0007 / 00-MASTER，摘要：

1. **独立 Rail「协作」**，不是 composer 里的会话模式。  
2. **逻辑成员持久，物理进程按需**（turn 级）。  
3. **任务真值在看板/room task**，聊天不能当唯一完成依据（S5 才深做）。  
4. **A2A 必须结构化**（S4），不能只靠自由文本 `@` 当协议（S3 的 `@` 只是**路由唤醒**，不是 A2A）。  
5. 文案用「协作室 / 成员 / 房间」，避免「数字员工自治」叙事。

## 3. 已实现能力（可手测）

### S1 — 静态壳

- Rail 入口 `collaboration`（chat 后）  
- 侧栏：列表 / 新建 / 选中 / 重命名 / 暂停 / 归档 / 恢复  
- 主区：时间线 + 输入框发**用户消息**（落盘）  
- 数据：`~/.tagent-dev/collaboration/{rooms,members,messages}.json`（prod：`~/.tagent/...`）

### S2 — 单成员真实 turn

- `appendUserMessage` → 异步 `triggerRunForMessage` → `ChannelBackendAdapter.runTurn`  
- 渠道：`createKsccSeatRunner` / `createPiHttpSeatRunner`（pi-core seat，与会诊同路）  
- **默认后端（0a18723）：kscc（启用且本机有 CLI）→ 外部渠道**  
- 新建成员自动 `pickDefaultMemberChannelBinding()`  
- Run 落盘 `runs.json`；状态 queued→running→done|failed|cancelled  
- 取消 run；启动恢复把遗留 running 标 **failed/INTERRUPTED**（不自动重放）  
- 幂等：`memberId:messageId`  

### S3 — 多成员并行 + 路由

- `parseCollaborationMentions`：无 @ → 协调者；`@displayName`；`@all` → 全体成员  
- `RoomScheduler`：房间 `maxConcurrentRuns` + 成员内串行 + FIFO 排队  
- 多目标各自 run，一方失败不影响另一方  
- UI：多条「思考中/排队中」、并发 x/y、添加成员  
- 新建默认 **协调者 + 开发** 两成员  

### 近期 hotfix

- **`window.prompt` 在 Electron 沙箱不可用** → `CollaborationTextPrompt`（重命名 / 添加成员）  
  commit `cf72c3f`

## 5. 数据与 IPC

| 文件 | 内容 |
|------|------|
| `rooms.json` | 房间元数据 |

## 6. 已知问题 / 粗糙点（用户已感知「问题很多」）

下一任优先消化这些，再开 S4 大功能：

### P0 体验 / 正确性

| # | 问题 | 线索 |
|---|------|------|
| P0-1 | **UI 仍粗糙** | 时间线 plain text 气泡；无 Markdown/附件；无流式打字 |
| P0-2 | **`window.alert` 可能也不稳** | 发送失败等仍用 alert；沙箱下可能异常，建议统一 toast/内联错误 |
| P0-3 | **无外部渠道且无 kscc** 时体验差 | 有系统警告，但 UI 引导弱 |
| P0-4 | **成员无法在 UI 改渠道/模型** | 只能自动绑默认；要换模型只能改 JSON 或待做设置 |
| P0-5 | **@ 与展示名强绑定** | 改 displayName 后历史 @ 语义乱；无 mention 补全 UI |
| P0-6 | **上下文投影过简** | 最近 12 条 chat 文本；无滚动摘要、无工作区文件感知 |

### P1 架构债

| # | 问题 | 说明 |
|---|------|------|
| P1-1 | **非事务多文件写** | createRoom 房间/成员分写；崩溃可能半状态 |
| P1-2 | **scheduler 纯内存** | 重启队列丢（有意：running→failed）；queued 也不会续跑 |
| P1-3 | **runTurn 非流式** | `onTextDelta` 接口有，renderer 未接 |
| P1-4 | **CLI worker 未接** | `backend==='cli'` 占位 |
| P1-5 | **协调者不自动拆任务** | 只是「被 @ 或默认应答的成员」 |
| P1-6 | **权限档位几乎未 enforce** | `permissionProfile` 字段在，run 侧未严控工具 |
| P1-7 | **侧栏/主区样式** | 部分复用 session 类名，视觉未按 01-UX 精修 |

### 已修（勿重复）

- Electron `prompt() is not supported` → `CollaborationTextPrompt`  
- 默认后端只认外部 → **kscc 优先**（`0a18723`）

## 10. 红线（给 agent 的硬约束）

1. 禁止把 room 消息写入普通 session JSONL 当「同一会话」。  
2. 禁止一个模型上下文扮演多个成员却标成多 Agent。  
3. 禁止未确认副作用时自动重放 interrupted run。  
4. 禁止 Agent 自行改成员权限/预算/无限拉人。  
5. 功能开发在 **`feature/collab-room`**；合 main 走 PR。  
6. 提交信息简洁完整句；不要无意义大重构。
