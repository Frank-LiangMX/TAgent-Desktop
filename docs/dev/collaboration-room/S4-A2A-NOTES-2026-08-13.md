### 2.2 service A2A 方法

`apps/electron/src/main/lib/collaboration/collaboration-room-service.ts`：

- `roomSend({ roomId, fromRunId, toMemberId, payload })`：异步通知，不暂停发送者；自环守卫；校验发送者深度；落 pending `message` 信封 + a2a_request 消息（visibility=participants）。
- `roomAsk({ roomId, fromRunId, toMemberId, question })`：提问；自环 + 深度守卫（`parentDepth` 由 `runDepth(runId)` 推导，**不接受外部传入**——安全字段宿主补齐红线）；落 pending `question` 信封（带 requestId）+ a2a_request 消息。
- `roomReply({ roomId, fromRunId, requestId, answer })`：回复；校验回复者=该 request 接收者（防伪造）；幂等阻断重复回复；落 `answered` reply 信封 + 原 question 信封置 answered + a2a_reply 消息。
- `markRunAwaitingPeer(runId)`：running → awaiting_peer（CAS）；释放调度器 slot + 成员回 idle + 广播 `run-awaiting-peer`。
- `runDepth(runId)`（私有）：从该 run 作为 causationId 已落盘信封取 max depth，无则 0。供深度守卫用。
- `listMailbox(roomId)` / `listPendingMailboxForMember(memberId)`：renderer 审计视图用。

`recoverInterruptedRuns()` 扩展：遗留 `awaiting_peer` run → `blocked`（continuation 已丢，02-spec §14 不自动重放，要求用户决定），与原 `queued/running → failed(INTERRUPTED)` 区分。

## 3. S4-3 待做（adapter 工具回路）

S4-2 实现了"宿主侧 A2A 入口"，但成员 turn 内**还无法主动调用** `roomAsk/Reply`——因为当前 `MemberBackendAdapter.runTurn` 返回 `Promise<MemberTurnResult>`（一次调用拿全文），没有工具调用回路。S4-3 需要：

1. 把 adapter 升级为 02-spec §12 的 `AsyncIterable<MemberEvent>`，或至少加一个 **host tool bridge** 回调通道（成员 turn 调 `room_ask` → host 执行 → 把 reply 注入 continuation）。
2. peer reply 到达 → 唤醒发送者新 turn：`roomReply` 成功后，把 reply 加入原 awaiting_peer run 的 continuation，重新入队（新 runId，幂等键含 requestId 防循环）。
3. 把 S4-1 的循环指纹接到调度器：A→B→A 近重复问答阻断。
4. `room_publish_artifact` / `room_task_update` / `room_request_user` 三个剩余 host 工具。

红线（不得降级）：
- 不得用 systemPrompt 文本协议代替结构化工具（02-spec §5 / 03-phases §12）。
- 安全字段（rootMessageId/causationId/depth/fromMemberId）始终宿主补齐。
