## 本次范围

在原有 Pi、Codex App Server、Claude Agent SDK / KSCC 三条路径上增加主会话手动切换。前后端实现由本机 `deepseek-v4.1-flash` 两路完成，主代理负责评审和集成验证。Grok 未产出实现，已停止其任务。工作树有大量此前未提交改动，本记录只说明本切片，不将其他改动计为本次交付。

输入区分别选择 Agent 和模型，模型列表仅显示该内核支持的渠道。新会话优先 Pi，缺少 API 配置时要求配置或明确选择其他 Agent；已有会话保持自己的绑定。当前回合必须先停止，切换成功后下一条用户输入才开始新内核的工作。

宿主校验目标渠道、模型、运行时、运行和审批状态，串行执行同一会话的切换。跨内核归档旧原生 ID，清空生效原生 ID，保存有界交接资料。聊天记录留在宿主；目标内核获得可见历史摘录，不迁移隐藏推理、正在执行的工具或原生状态。

## 评审重点

- 不能把发送函数返回或停止请求获受理，误当成原生回合完成。
- 交接尝试需区分成功、失败和结果未知；错误结束不能清空交接记录。
- 前端同步阻止重复切换，并忽略切走会话后到达的旧请求结果。
- 通用元数据更新不能绕过专用切换事务；前后端都不能静默回退到 KSCC。
- 读取历史、停止旧内核、验证目标失败时要报告错误，不能假装完成交接。

集成时另修正三点：旧请求完成不能解除新会话的切换锁；缺失或错配的 IPC 返回不能合成为成功；比较元数据变更时保留旧原生 ID，避免旧 Codex 会话仅重命名也被误拦。发送入口增加同步锁检查，组件卸载时作废旧请求。

## 尚未覆盖

1. 交接先采用约 12,000 字符可见历史、约 14,000 字符总预算，并非按目标模型 token 容量自动计算。早期和中段约束可能省略；附件路径仅为线索。
2. 等待观察到旧回合终态，不等于已验证所有工具子进程退出；并行写任务的工作区隔离尚未交付。
3. 跨内核每次新建原生上下文；原生 ID 归档用于追踪，尚未实现安全恢复旧绑定并补增量。
4. 投递中断、原生输出后失败及重启的未知状态仍需专门的可视化与恢复入口；不得表述为“无损切换”。
5. 逐条消息 Agent 标识、可展开交接详情、统一 Agent 预设，以及标准 Claude Code 独立接入尚未完成。当前第三条路径是现有 KSCC。
6. 尚未实现自动故障转移、新的多 Agent 并行入口或任意模型到任意原生内核的协议代理。Pi 的 HTTP 模型不能因此直接用于 Claude Code。

## 后续实机验收

使用专门测试会话验证 Pi → Codex → KSCC → Pi，包含多轮、工具、停止、审批、目标不可用和重开。确认界面选择与实际执行内核一致，历史与成果保留，错误不伪装为成功，切换不放宽原权限。在此之前，本记录不代表阶段 A–D 已发布或长期稳定性已验证。
