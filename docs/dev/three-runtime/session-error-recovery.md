# 会话出错后的显式恢复

## 用户入口

自动重连耗尽或当前回合失败后，在输入框上方的错误条提供：

- **继续当前模型**：使用当前绑定发送一条短的继续指令，不重发原任务、附件或会诊请求。
- **换模型继续**：先选择当前内核兼容的渠道 / 模型，再确认切换并继续。
- **换内核接力**：先选择 Pi / Codex / Claude Code 及其兼容渠道 / 模型，再确认接力。

选择阶段只修改界面草稿；取消不会修改会话。非重试类错误不提供原配置直接重试，但允许显式选择其他渠道。Chat 模式限制错误继续沿用原来的提示，不通过恢复改变执行形态。

## 恢复的实际含义

手动恢复是用户明确发起的**新回合**，不是重新运行原任务，也不是恢复隐藏推理。短指令要求核对已有进度和工具结果，仅处理未完成部分；对结果不明、可能产生外部影响的操作，先核实，无法核实就询问用户。

- Pi 的存活内存会话保留原始用户消息、成功工具调用和结果，只移除末尾 error / aborted 助手消息。
- Pi 自动重连仍在原回合内使用 `agent.continue()`；手动继续使用短指令 `agent.prompt()`，新回合拥有自己的重连预算。
- 切换渠道、模型或内核复用 `switchSessionRuntime` 事务。它会停稳旧实例、建立新绑定，并带入有预算的可见历史节选；不是完整迁移。原完整记录仍在会话历史中。
- 重启后按现有原生 resume 或面板可见历史恢复路径执行，不能宣称恢复了完整 Pi 内存状态。
- 不自动换模型、不转换不兼容协议、不放宽权限、不保证任意外部操作恰好执行一次。

## 失败与并发

- 前端同步锁阻止重复点击，也阻止恢复期间其他发送和绑定选择；后端另行验证是否允许恢复。
- 主进程只接受既有、未归档的普通主会话恢复；已有发送、MoA、原生回合、停止收尾或审批等待时拒绝。请求中的绑定仅用于校验是否过期，执行配置和权限以已保存会话为准。
- 恢复校验拒绝只返回本次请求失败，不广播会话运行失败，避免另一窗口正在运行的回合被界面误标为停止。
- 切换失败不投递继续指令；切换已成功但发送失败时，新绑定保留，提示恢复失败，允许用户重试，不反向自动切回。
- 切换期间离开会话，过期完成不能再投递继续指令。
- 发送受理后只清除触发恢复的那条旧错误，不能清掉新回合刚产生的错误。
- `model_manual_recovery` 是不落盘的控制事件；前端只清指定 UUID 的未完成 partial，不删除已完成输出或工具结果，也不显示自动重连倒计时。

## 验收方式

使用纯流程测试、React DOM 交互测试、隔离会话存储和回环 HTTP 测试。不调用公司网关、不重跑真实用户任务；这些测试不等于桌面实机体验验收。

2026-09-17：17 个相关测试文件、216 项测试全部通过，包含原有自动重连和切换事务回归。真实 Pi + 回环 HTTP 验证了成功工具后发生终端认证错误，显式继续请求中原任务仅出现一次、工具结果保留、工具只执行一次，失败助手不进入新请求。根目录类型检查、生产构建及 `verify:main` 通过。本次只更新代码 / 构建产物，未更新 `apps/electron/out` 安装包。

界面按 ui-ux-pro-max 的错误就地反馈、显式确认、可访问控件和现有主题一致性规则实现；该技能附带搜索脚本在本机缺失，因此未运行其设计系统生成器。
