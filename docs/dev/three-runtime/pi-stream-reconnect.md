# Pi 临时断流自动重连

## 问题与范围

实机会话出现 `Upstream response stream was interrupted`。原有 Pi 重试分类遗漏该上游文案，直接交付错误终态；仅扩充字符串匹配还不足以保证停止、半截输出和界面状态正确。

本改动只处理 Pi 主循环中的暂时性模型请求失败，不自动切渠道/内核，不重启 Codex/Claude 官方进程，不重放整个用户任务。鉴权、余额/配额、用户主动停止、未知错误不进入此重试路径。

## 行为契约

- 自动重连最多 5 次，退避 1、2、4、8、16 秒；这是整轮任务的额外重连预算，不无限重置。
- 保留原始用户输入、成功的 assistant 工具调用及对应工具结果，从失败模型请求继续。已完成的工具不因宿主重新提交原始 prompt 而重放。
- 暂时失败不向宿主交付结束回合的 result，也不提前显示错误横幅。只有重试耗尽或不可恢复错误才结束。
- `model_reconnecting` 控制事件携带 `attempt/maxAttempts/delayMs`，可附 `discardedAssistantUuid` 清理失败请求的未完成快照；只移除该 UUID 的 partial，不删除先前成功消息。`model_reconnect_cleared` 清除提示。状态不混入聊天转录、模型上下文或历史落盘。
- 聊天底部一条“正在重新连接 n/5”原地更新，保持运行计时和停止按钮。会话切换不丢状态；成功、失败、停止、新回合清理提示。
- 用户停止取消退避和在飞请求；停止之后不能偷偷继续请求。失败消息内未完成的工具参数不能被当作已成功的工具调用执行。

## 边界

这是宿主层保留已有工具结果的续跑，不是网络层从某个 token 精确续传；失败请求可能已经被上游计费。模型恢复后仍可能自主再次提出相同操作，不能据此承诺任意外部副作用 exactly-once。进程重开后的恢复、跨模型交接及错误横幅手动“重试”的既有行为不在本切片内。

## 验证

主代理独立验证：

- UI/run/runtime 7 文件 64 项通过；最终 Pi 3 文件 37 项通过，共 101 项聚焦回归。不是全仓测试通过声明。
- Pi 回归包含 4 项真实 Pi Agent + 本地 HTTP 测试：Chat/Responses 均先执行工具，再模拟半截工具参数 EOF 和上游中断，最后成功；另测退避期停止和在飞 HTTP 重连停止。
- 每条恢复链路验证原始用户消息只出现一次、保留成功工具结果、工具执行次数为 1、半截工具不执行、暂时失败不透传 assistant.error、只产生一条成功终态。停止测试没有下一次请求，只产生 interrupted 终态。
- 分类、5 次耗尽、预先取消、停止后的迟到错误、单行可访问状态、会话切换、失败 partial 清理与计时不重置均有回归。
- 根目录 `bun run typecheck` 通过；renderer 构建通过（保留原有大 chunk/混合导入提示）。
- 最终同一工作树一次运行 10 文件、101 项全部通过。`verify:main` 通过；包内 main/preload/renderer 与当前构建逐字节一致，包含新重连事件及 Responses EOF 判定；用打包 Electron 验证 SQLite 内存查询和 Claude SDK 解析通过。

使用回环 HTTP、伪凭据、隔离测试工具，不重跑用户的真实任务。不等于公司网关稳定性或桌面 UI 实机全部验收通过。
