# 主会话所属的子代理（班组暂停）

日期：2026-09-17。此文记录本轮实现及验收边界，不代表真实渠道端到端验收已完成。

## 产品约定

主会话负责理解需求、拆分、选型、验收和最终回复。当前只启用子代理，处理边界清楚、可独立验收的任务；不是另一个独立聊天入口，也不能递归扩张自己的团队。

班组 / 看板暂时停用，等确有持久任务编排需求时再改造。当前不提供派工入口、不向模型注册看板工具、不启动后台调度；旧客户端强制派工和旧队列重启也不能绕过暂停。保留已有数据、偏好和底层实现，不做清库或迁移。产品门控为共享常量 `CREW_ORCHESTRATION_ENABLED=false`，不是用户设置开关；恢复前需重新评审任务依赖、恢复语义和交互，不能仅改常量就视为完成。

内核与模型分开：Agent 预设选择执行内核和权限上限；渠道/模型选择算力。普通子任务默认用 Pi 执行循环，继承主会话实际渠道与模型；显式选择官方 Agent 预设时使用独立 Codex 或 Claude Code 适配器，不通过旧 CLI 工人池自动猜选。

## 配置与入口

- 渠道页：配置 API Key、协议和启用模型。
- 设置 → 子代理调度：子代理并行上限；每个模型可声明强度、速度、成本、擅长任务，或禁止参与派发。画像显式保存，不是性能基准。沿用原偏好存储，保留暂不展示的班组字段。
- Agent 目录：为可调用预设绑定内核和兼容渠道/模型，配置只读、后台运行和派发确认。
- 主模型使用 `list_delegation_models` 查询实时候选，再使用 `task`。Claude Code 的宿主工具带 MCP 命名空间。普通 Plan 规划不依赖班组，继续可用。

## 效率规则

1. 小任务主会话直接完成。能独立拆分且收益明确才委派，避免多名工人重复检索或修改同一文件。
2. 优先满足能力，再比较速度与成本。未校准画像为 `unknown`，不按模型名字伪造能力排名，也不假设未知模型便宜或快速。
3. 显式选型提供 `selectionReason`，可提供 `complexity`。已标为 `standard` 的模型不可承接 `complex` 任务；未知能力的风险由主会话说明和验收。
4. 默认继承主会话模型；跨渠道明确指定模型。不按角色池、数组顺序或可用工人列表静默换模型。
5. 同一主会话的子代理共用并发额度，前台等待不绕过上限；收到停止请求不立即释放额度，待实际执行结束后释放。底层保留与班组共享额度的能力，但班组暂停期间不会占用新的执行额度。

## 安全与回传

- 子任务权限不得高于主会话及 Agent 预设。无权限处理器时拒绝执行；后台工人无法安全审批的操作应阻塞并反馈，不默认放行。
- 显式要求派发确认的预设必须得到用户同意。停止后不得由迟到的子任务回调自动唤醒主会话。
- 官方子内核独立创建、取消和销毁；它的结束状态不冒充主会话结束。成功必须有明确成功终态，流意外结束不算成功。
- Codex 子任务默认使用原生只读沙箱，额外写操作经父权限审批；不批量授予原生扩展权限。Claude Code 通过原生权限回调继承父权限，禁用原生递归 Agent/Task。
- 阻止原生递归派发绕过宿主并发限制。旧 CLI 路径不能保证权限继承时拒绝使用。
- 本轮不提供临时工作区或跨工作区写入隔离；固定工作区与主会话不一致时拒绝，不静默忽略配置。
- 子任务回传是待验收材料，而非新用户命令；主会话核对成果后整合答复。

## 尚不承诺

本轮不提供自动测速排名、服务质量探测、自动故障换模、写冲突自动合并或无损上下文迁移。官方内核仍受协议与原生沙箱能力限制，不能认为任何模型在任何内核上都可用。

本轮自动化验证使用假适配器、临时配置和本地回环服务；不消耗公司真实 API，不更改用户已有渠道配置。正式接入仍需真实渠道验收，安装包需另行构建。
